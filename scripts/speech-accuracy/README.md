# Speech accuracy evaluation

The fixed human corpus is VCTK (Christophe Veaux, Junichi Yamagishi and Kirsten MacDonald), licensed CC BY 4.0: https://datashare.ed.ac.uk/handle/10283/3443 . `corpus.json` records the exact archive revision, member names, reference, attribution, transformations and SHA-256 for every WAV. Audio is retained here for reproducibility; it is not placed in `public/` or shipped to visitors.

There are 36 distinct human utterances, with three speakers (18 clips) per partition. Speakers p248 and p251 are Indian English according to VCTK's `speaker-info.txt`; they belong to different partitions. The remaining speakers are English. References are distinct across partitions. Each speaker contributes three clean utterances, one 1.25× speed transformation, one with seeded Gaussian noise at 15 dB signal-to-noise ratio, and one attenuated to 10% amplitude. Speed and noise are controlled transformations, not naturally fast speech or recorded environmental noise. VCTK does not cover the requested modern AI terms; no technical-term accuracy can be inferred from it.

`prepare-corpus.py` uses HTTP ranges rather than downloading the entire archive. Requires Python `remotezip`, `requests`, `numpy`, and system `ffmpeg`. Run once before any model comparison, then retain the frozen manifest and audio. Do not regenerate the manifest between experiments.

`run.mjs` starts a minimal Vite server on 5193, runs one Chromium and one model, and closes both in `finally`. It exercises production engine code via a Web Audio source connected to a MediaStream, or the production worker in batch mode. This is digital audio injection: neither a physical microphone nor an acoustic echo-cancellation test. It does not run the full Playwright suite. No COOP/COEP headers are configured. The harness records CDP page throttling, but calibration showed that it does not slow the ASR worker. The locked stress condition instead uses a direct renderer CPU limiter; timings are measured, never multiplied. Headless Chromium may have no GPU adapter; report this explicitly rather than claiming measured WebGPU speed.

Results preserve hypotheses and timestamps. `summarize.mjs` uses corpus-weighted word error rate (WER), with lowercase ASCII word tokens, punctuation as separators, and apostrophes retained. WER is not corrected for model spelling variants. Technical terms use complete token sequences rather than substring matches. Predeclared orthographic variants include XG Boost / X G Boost and BM-25 / B M 25. No fuzzy semantic matches are credited. Zero annotated terms means unavailable, not 100% accuracy. First word latency includes capture, polling, queueing, and inference; `inferMs` alone is not end-to-end live lag.

Tune and select on `--split=tune`. Freeze the decision before examining `--split=heldout`. Held-out baseline runs may be captured beforehand, but their hypotheses and metrics must remain unread until selection is frozen. Report the held-out partition only as evaluation results; do not revise the configuration based on it.


Five additional real conference excerpts in `human-terms.json` cover XGBoost, RAG, LoRA, embeddings and BM25. These are **held out only**, with no speaker in the VCTK tuning partition. They were chosen from published FOSDEM captions before running ASR on them. Source video, caption hash, license link, attribution, exact start/end times and modifications are recorded per excerpt. The video archive directory footers identify CC BY 2.0 Belgium; retained license evidence covers all source directories. The LoRA annotation was independently checked on the speaker's slide at video time 946 seconds ("Support LoRA adapters"); its caption spells the acronym "lower".

These captions contain transcription mistakes. They remain unchanged to avoid editing references toward model outputs. Use this five-clip challenge to score technical-term presence, **not gold-reference WER**. `summarize.mjs --human-terms` leaves WER unavailable and labels any caption disagreement rate separately. There are 41 distinct human recordings in total: 18 VCTK tuning clips and 23 held-out clips across VCTK and FOSDEM. The two sequence diagnostics reuse VCTK recordings and are not independent clips. The ten eSpeak clips remain supplemental synthetic diagnostics.

Live latency in the locked runs measures time from source playback to first published text **before speech ends**. Runs with no live text have a null latency and are counted in the coverage column; they are not treated as zero latency or folded into a misleading mean. `liveText` is the snapshot at speech end. `firstOutputMs` also records a later first output during finalization. Finish time includes the final capture drain, queued work, first-use model download, and decoding. Captured/source sample counts and playback wall time are retained to expose the effects of CPU duty cycling.

The renderer-only `cpulimit` experiment gives the Chromium process containing the ASR worker a 25% CPU budget. CDP page throttling does not throttle that worker, and the user systemd scope lacks the CPU controller. Run the calibration script to verify this on another Chromium version. CPU duty cycling can also affect audio capture and is not equivalent to every low-end phone.

`evaluate-heldout.mjs` verifies frozen source and manifest hashes, runs each historical/current profile sequentially, and refuses to overwrite a completed run. No held-out hypotheses are used for configuration changes. Completed pilot captures made before locking are retained for audit; the report uses only the preregistered `evaluation-*` files.

A supplemental worker-only condition was preregistered after the renderer-starvation limitation was observed. It changes scheduling only: frozen recognition settings and source stay identical. `thread-throttle.mjs` pins ASR workers and three nice-5 CPU burners to one logical CPU, excluding other renderer threads. The launcher must also have nice 5; calibration is required before ASR. The measured independent slowdown was 3.60×, an approximation of 4× stress. `worker-throttle-protocol.json` records the registration time, source hashes and planned runs. The unfavorable renderer-wide results remain part of the report.

Upstream caption files and `vctk-speaker-info.txt` are retained byte for byte, including trailing whitespace and final blank lines. Their original hashes and attribution take precedence over formatting cleanup.

The 2026-11-09 user-requested follow-up is separate from the original frozen evaluation. The user explicitly requested a measured slow-device guard and question-term prompting after reviewing the original held-out results. `followup-protocol.json` registers the new fixed policy and jobs; `evaluate-followup.mjs` checks its hashes. `report-followup.mjs` reports only the previously held-out human recordings, including an unrelated-prompt negative control. These are follow-up measurements on exposed test data, not an untouched validation estimate. To reproduce the original frozen configuration, use commit `00f62fcc` in a separate checkout; current runtime files intentionally no longer match that original freeze.
