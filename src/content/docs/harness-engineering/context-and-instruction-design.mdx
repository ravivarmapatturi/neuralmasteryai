# Context & Instruction Architecture

In modern AI engineering, the way documentation and rules are provided to an agent is as critical as the code itself. Developers often believe that more context is always better—dumping thousands of lines of documentation, architecture manuals, and code snippets into an instruction file.

In practice, this causes **instruction rot** and **attention dispersion**. Frontier transformers suffer from the "lost-in-the-middle" effect: the larger the context, the less reliably the model obeys individual constraints.

This chapter details the architecture of agent-readable workspaces and instruction budgets.

---

## 1. The Instruction Budget

A production harness treats token space like CPU cache. Every instruction carries an **opportunity cost**:

```
┌─────────────────────────────────────────────────────────────┐
│             THE 32,000 TOKEN HARNESS CACHE BUDGET           │
├──────────────────────────────┬──────────────────────────────┤
│ 1. Core System Rules         │ 2,500 tokens (Immutable)     │
│ 2. Scoped AGENTS.md / Map    │ 3,500 tokens (Workspace Map) │
│ 3. Active Tool Schemas       │ 2,000 tokens (Permitted APIs)│
│ 4. State Checklist           │ 1,500 tokens (Progress JSON) │
│ 5. Working Task Buffer       │ 22,500 tokens (Diffs & Logs) │
└──────────────────────────────┴──────────────────────────────┘
```

If the static rules (items 1 to 4) exceed 10,000 tokens, the agent's reasoning capacity degrades exponentially:
- It forgets negative constraints ("do not edit files in `/tests`").
- It hallucinates deprecated functions listed in outdated docs.
- Each iteration becomes prohibitively expensive in latency and cost.

## 2. The "Map vs Manual" Principle

The core rule of agent context design (established by projects like *learn-harness-engineering*):

> **Never give an agent a manual when you can give it a map.**

```
       WRONG: THE MANUAL TRAP                       RIGHT: THE MAP PATTERN
 ┌─────────────────────────────────┐         ┌─────────────────────────────────┐
 │ • 2,000 lines of API specs      │         │ • 150-line index of components  │
 │ • Complete data models          │   VS    │ • File paths & key exports      │
 │ • 20 worked examples            │         │ • Commands to run tests & build │
 │ • Outdated markdown tutorials   │         │ • Tools to fetch files on-demand│
 └─────────────────────────────────┘         └─────────────────────────────────┘
  Result: Model confused, slow,               Result: Fast, sharp, fetches only
  hallucinates conflicting APIs.              the exact files it needs to edit.
```

## 3. The `AGENTS.md` Standard

Industry-standard harnesses use structured markdown files placed in the repository root to establish the project map:

```markdown
# Repository Map for AI Agents (Python Stack)

## Core Tech Stack
- Backend & ML: Python 3.12 + FastAPI + PyTorch + Pydantic v2
- Tooling: uv / poetry for environment isolation
- Verification: pytest (`pytest -v`), mypy (`mypy --strict`), ruff (`ruff check .`)

## Build & Verification Commands
- Static audit & lint: `ruff check . && ruff format --check .`
- Type validation: `mypy --strict src/`
- Unit test suite: `pytest tests/unit/ -v`
- Integration / smoke test: `pytest tests/e2e/ -v`

## Code Invariants
- NEVER use bare `try/except Exception: pass` to swallow errors.
- All function parameters and return types must carry explicit PEP 484 type annotations.
- NEVER edit files in `tests/` to manufacture artificial passes without user authorization.
- Always execute the 3-layer verification pipeline before committing changes.

## Directory Structure
- `src/models/`: PyTorch neural architectures and attention kernels.
- `src/harness/`: Agent execution loops, sandbox runners, and verification sensors.
- `tests/`: Deterministic pytest fixtures and property-based regression suites.
```

### Hierarchical Scoping

In multi-package or monorepo environments, instructions are scoped hierarchically:

```
project-root/
├── AGENTS.md                  # Sitewide architectural map & global invariants
├── packages/
│   ├── web/
│   │   └── AGENTS.md          # Web-specific commands & styling rules
│   └── api/
│       └── AGENTS.md          # Database migration rules & API schemas
```

The harness automatically loads only the `AGENTS.md` relevant to the directory the agent is currently working in.
