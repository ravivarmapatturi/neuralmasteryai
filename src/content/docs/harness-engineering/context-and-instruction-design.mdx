# Context & Instruction Architecture

In modern AI engineering, the way documentation and rules are provided to an agent is as critical as the code itself. Developers often believe that more context is always better—dumping thousands of lines of documentation, architecture manuals, and code snippets into an instruction file.

In practice, this causes **instruction rot** and **attention dispersion**. Frontier transformers suffer from the "lost-in-the-middle" effect: the larger the context, the less reliably the model obeys individual constraints.

<ELI5>

Imagine asking someone to assemble a piece of furniture, and instead of giving them a 1-page quickstart diagram, you hand them a 400-page encyclopedia detailing the chemical composition of the screws and the history of woodworking. They get overwhelmed, lose track of the core instructions, and make silly mistakes.

In Harness Engineering, we keep instructions razor-sharp. We give the agent a compact **Map** of where things live, and let it pull detailed manuals only when it specifically needs them.

</ELI5>

## 2. Dynamic Compaction & Token Pressure

As an agent edits code, executes tests, and receives compiler outputs, its working memory fills rapidly. A robust harness continuously compacts conversational history into structured external state:

<ContextCompactionVisualizer />

<GoDeeper title="Go deeper: Why attention dispersal creates 'Context Anxiety' in long-running runs">

In multi-turn autonomous coding runs, agents often exhibit what researchers term **Context Anxiety**: as the token count crosses 60-70% of the active context window, the model's likelihood of abruptly declaring premature victory or emitting truncated code spikes dramatically. 

This occurs because frontier models are fine-tuned on completion pairs where conversational turn length is bounded. To eliminate Context Anxiety, the harness enforces a **sliding context window**: raw execution trace logs (stdout/stderr) are purged after each turn and replaced by a deterministic state checklist (`feature_list.json`). The agent always operates with 70%+ empty headroom for reasoning.

</GoDeeper>

## 3. The `AGENTS.md` Standard

Industry-standard harnesses use structured markdown files placed in the repository root to establish the project map:

```markdown
# Repository Map for AI Agents (Python Stack)

## Core Tech Stack
- Backend & ML: Python 3.12 + FastAPI + PyTorch + Pydantic v2
- Tooling: uv / poetry for environment isolation
- Verification: pytest (`pytest -v`), mypy (`mypy --strict`), ruff (`ruff check .`)

## Build & Verification Commands
- Static audit & lint: `ruff check . && ruff format --check .`
- Type validation: `mypy --strict src/`
- Unit test suite: `pytest tests/unit/ -v`
- Integration / smoke test: `pytest tests/e2e/ -v`

## Code Invariants
- NEVER use bare `try/except Exception: pass` to swallow errors.
- All function parameters and return types must carry explicit PEP 484 type annotations.
- NEVER edit files in `tests/` to manufacture artificial passes without user authorization.
- Always execute the 3-layer verification pipeline before committing changes.
```

## 4. AST-Extracted Repository Mapping in Python

Instead of dumping raw source code, a production harness uses Python's built-in `ast` module to dynamically extract a lightweight architectural skeleton. 

Run this live in-browser Python implementation to see how an AST parser extracts an 85% compressed map:

<RunnableCode code={`import ast

sample_code = """
import torch
import torch.nn as nn
from typing import Optional, Tuple

class MultiHeadAttention(nn.Module):
    '''Scaled dot-product multi-head attention module.'''
    def __init__(self, d_model: int = 512, n_heads: int = 8):
        super().__init__()
        self.d_model = d_model
        self.n_heads = n_heads

    def forward(self, q: torch.Tensor, k: torch.Tensor, v: torch.Tensor, mask: Optional[torch.Tensor] = None) -> Tuple[torch.Tensor, torch.Tensor]:
        '''Compute attention outputs and normalized weights.'''
        # In a real file, 80 lines of tensor math live here...
        pass
"""

def extract_ast_skeleton(code: str) -> str:
    tree = ast.parse(code)
    lines = []
    for node in tree.body:
        if isinstance(node, ast.ClassDef):
            lines.append(f"class {node.name}:")
            doc = ast.get_docstring(node)
            if doc:
                lines.append(f"    '''{doc}'''")
            for item in node.body:
                if isinstance(item, ast.FunctionDef):
                    args = [a.arg for a in item.args.args]
                    lines.append(f"    def {item.name}({', '.join(args)}): ...")
    return "\\n".join(lines)

print("=== Raw Code (45 lines of implementation) ===")
print(f"Raw character length: {len(sample_code)}")

skeleton = extract_ast_skeleton(sample_code)
print("\\n=== AST-Extracted Map (Compact Index) ===")
print(skeleton)
print(f"\\nSkeleton character length: {len(skeleton)} -> {(1 - len(skeleton)/len(sample_code))*100:.1f}% token reduction!")
