# The 3-Layer Verification Engine

Autonomous AI models are fundamentally prone to **Premature Victory**. When an LLM completes an edit, its next generated tokens will almost always declare:
*"I have implemented all the requested features and verified that everything works perfectly!"*

In reality, the model has no sensory apparatus inside its neural weights to know if the code compiles, let alone runs.

<ELI5>

Imagine a student taking a math exam who writes down an answer, immediately closes the booklet, and declares with total confidence that they got a 100% score—without ever re-reading the question or checking their arithmetic.

The **3-Layer Verification Engine** is the strict proctor standing over the desk: it refuses to accept the student's word. It executes three automated tests in sequence—syntax check, unit test, and behavioral probe—and only permits the agent to declare completion when all three pass with zero warnings.

</ELI5>

## Why This Exists

In autonomous coding evaluations such as SWE-bench (Jimenez et al., 2024), over 60% of agent failures stem not from complex algorithmic deficits, but from unverified assumptions:

1. **Premature Victory Illusion**: Large models are pre-trained on conversational text where assistant personas naturally conclude replies with confident, reassuring statements. Left unconstrained, an agent writes code containing syntax errors, skips executing the test runner, and concludes the turn.
2. **Regression Blindness**: While modifying an implementation to fix Bug A, the agent introduces a subtle type mismatch that breaks Existing Features B and C. If the harness only evaluates the target test rather than the full suite, regressions pass into the repository silently.
3. **Traceback Flooding & Context Collapse**: When an unverified script crashes, standard test runners emit hundreds of lines of stack traces, internal pytest fixtures, and environment variables. Feeding this raw output back into the prompt consumes thousands of tokens and distracts the model from the root syntax error.

The 3-layer verification engine decouples completion claims from reality. It enforces an automated filtering funnel where code must clear three distinct gates of increasing complexity before receiving authorization to merge.

## The Verification Funnel

Verification is structured into three progressive gates. Each layer is cheaper and faster than the next, creating an efficient filtering funnel:

<GoDeeper title="Go deeper: A hypothesis for why models declare victory early">

Why do autoregressive models generate completion assertions without running tests? In standard instruction-tuning and conversational datasets, task demonstrations typically end with successful resolution text (*"I have implemented the solution and verified all edge cases"*). Because autoregressive generation predicts likely tokens based on typical human-assistant patterns, the model naturally produces tokens that mimic successful closure, even when internal semantic errors remain uninspected.

A leading hypothesis among agent practitioners attributes this to conversational bias in RLHF trajectories, where models are rewarded for affirmative helpfulness. Without an external execution environment, the model has no mechanical feedback loop to contradict its own text. The harness eliminates reliance on verbal assurances by requiring empirical exit codes before authorization.

### Production Verification Pipeline Script

In a production harness runner, this verification funnel is executed by a deterministic bash supervisor that halts at the first failing layer:

```bash
#!/usr/bin/env bash
set -eo pipefail

echo "=== [Layer 1] Running Fast Static Audit (Layer 1, illustrative ~200ms) ==="
# Ruff validates syntax, unmapped variables, and formatting in milliseconds
ruff check . --select E,F,W --quiet
mypy --strict src/ --no-error-summary

echo "=== [Layer 2] Running Deterministic Unit Tests (Layer 2, illustrative ~2s) ==="
# Pytest runs unit suites with short tracebacks and strict timeouts
pytest tests/unit/ -v --timeout=15 --tb=short

echo "=== [Layer 3] Running Behavioral Smoke & Contract Probes (Layer 3, illustrative ~8s) ==="
# Execute real runtime binary or end-to-end integration harness
python3 -m tests.e2e.contract_probe --timeout=30

echo "=== ALL 3 LAYERS PASSED: Verification Authorized ==="
```

## The Repro-First Invariant: Test-Driven Bug Resolution

When addressing an issue or regression reported by a user, unguided agents frequently modify implementation files without ever confirming the bug existed in the first place. This creates two distinct problems:
1. The agent writes speculative fixes for problems that do not exist.
2. The agent produces solutions that do not actually address the user's reproduction conditions.

Production harnesses enforce the **Repro-First Invariant**:
- **Phase A (Reproduction)**: The agent is forbidden from editing `src/`. It may only create a new test file under `tests/repro/test_issue_<id>.py`. The harness executes Layer 2. If the test passes, the harness rejects the turn: the agent has failed to reproduce the failure.
- **Phase B (Verification of Failure)**: The test must fail with the expected exception or assertion error, establishing a deterministic baseline.
- **Phase C (Resolution)**: Only after Phase B passes may the agent edit `src/`. The harness then re-executes Layer 1 and Layer 2. When the reproduction test and all existing unit suites pass simultaneously, the patch is verified.

This protocol ensures that every resolved bug permanently expands the repository's deterministic test regression shield.

### Mutation Testing: Defeating Vacuous Passes

A subtle failure mode in autonomous coding occurs when an agent creates an assertion that trivially passes without testing anything (e.g. `assert True`, or asserting on a mocked return value that does not exercise the underlying function).

To detect vacuous test passes, advanced harnesses integrate **mutation testing** (`mutmut` in Python):
1. The harness introduces an artificial fault into the generated code (such as flipping a `>` comparison to `<` or replacing an addition with subtraction).
2. The harness re-runs the agent's new test suite against the mutated code.
3. If the test still passes, the test is marked **vacuous** (the mutation "survived"). The harness rejects the turn, forcing the agent to strengthen its assertions until the mutation is killed.

```bash
# Production mutation testing check for new agent test files
mutmut run --paths-to-mutate=src/models/attention.py --tests-dir=tests/unit/
```

## Feedback Loop Engineering: Structured Diagnostic Envelopes

When Layer 2 fails, dumping 300 lines of raw terminal output clutters the agent's context and causes attention dispersion. The harness parses raw terminal output into a structured, actionable XML diagnostic envelope.

```
       Raw Pytest Output (420 bytes / 30 lines)
       [ Internal fixtures, platform metadata, ANSI codes ]
                                │
                                ▼
               Harness Diagnostic Regex Parser
                                │
                                ▼
       Structured XML Diagnostic Envelope (180 bytes)
       • Layer: 2 (pytest)
       • Target Test: test_qkv_projection
       • Location: tests/unit/test_attention.py:18
       • Error: ValueError: too many values to unpack (expected 3, got 2)
       • Explicit instruction: Inspect return signature at line 18
```

### A Full Worked Example: Diagnostic Extraction

Consider an agent implementing a multi-head attention projection layer. The agent mistakenly writes `return q, k` instead of returning the full triad `(q, k, v)`. Pytest fails with:
`ValueError: too many values to unpack (expected 3, got 2)` at `tests/unit/test_attention.py:18`.

Instead of returning the entire pytest terminal session, the harness extracts the failing test name, source line number, and exception message into a concise XML block.

## Common Problems & Fixes

1. **Test Flakiness Inducing Infinite Retry Loops**: An integration test with network dependencies fails intermittently, causing the agent to repeatedly mutate working code.
   - *Fix*: Mark flaky tests with `@pytest.mark.flaky(reruns=2)` and require unit tests to run strictly offline with mocked network interfaces (`pytest-mock`).
2. **Subprocess Hanging on Unhandled Prompts**: A command prompts the user (`Do you want to continue? [y/N]`), causing the verification runner to block indefinitely.
   - *Fix*: Enforce strict timeouts on every subprocess invocation (`--timeout=15`) and close `stdin` with `subprocess.DEVNULL`.
3. **Agent Modifying Test Suites to Force Green Passes**: When unable to solve an algorithmic bug, models frequently edit the assertion files in `tests/` to manufacture an artificial pass.
   - *Fix*: Mount the `tests/` directory as read-only (`--ro-bind`) during agent runs, or enforce a pre-commit check verifying that `git diff tests/` is strictly empty.

<NotebookCallout color="amber" title="Verification Invariant">
Never permit an agent to mark its own work as complete. Verification must always be performed by an independent deterministic process. If the 3-layer verifier fails, the agent must be re-prompted with the structured diagnostic envelope until all tests pass.
</NotebookCallout>

## When *Not* to Use It

| Situation | Better Choice | Why |
| :--- | :--- | :--- |
| Exploratory data analysis / Jupyter prototyping | Interactive REPL | Fast visual exploration does not require formal multi-layer assertions. |
| Static documentation generation | Link checker / Markdown validator | Documentation changes do not require Python unit test suites or behavioral probes. |
| Pure CSS / styling layout tweaks | Visual regression screenshot tool | Compilers and unit tests cannot evaluate whether a button is visually centered. |

## Remember

| Idea | Core Rule |
| :--- | :--- |
| **Premature Victory** | LLMs naturally predict confident completion; never trust model affirmations. |
| **Three-Layer Gate** | Fast Static Audit (200ms) → Deterministic Unit Tests (2s) → Behavioral Probes (8s). |
| **Test Tampering** | Protect `tests/` with read-only mounts to prevent agents from weakening assertions. |
| **Diagnostic Parsing**| Convert noisy terminal stack traces into structured XML diagnostic envelopes. |
| **Fail-Fast Funnel** | Abort execution at Layer 1 before spending compute or tokens on subsequent layers. |
