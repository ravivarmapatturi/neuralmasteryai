# Autonomous Loops & Supervisors

The defining characteristic of an autonomous agent is its ability to operate in an unattended cybernetic loop: receiving an open-ended goal, decomposing it into subtasks, executing code modifications, verifying results against compilers, and iterating until all requirements are met.

However, unbounded autonomous loops introduce critical engineering failure modes: **infinite oscillation cycles**, **runaway token expenditure**, and **drift from the original specification**.

<ELI5>

If you ask an autonomous agent to build a multi-page app without supervision, it is like leaving an over-enthusiastic junior developer alone in the office for an entire weekend: they might rewrite the database schema, install 30 conflicting libraries, get trapped in an endless loop trying to center a button, and burn $500 in cloud credits.

The **Supervisor Harness** provides the physical guardrails: it limits the number of attempts, halts execution when the agent loops in circles, and assigns an independent "Checker" agent with a clean context to approve every commit.

</ELI5>

## Why This Exists

A conventional assistant operates in a **Single-Turn Request/Response** mode: the human engineer evaluates every line of diff, catches errors, and manually prompts the next step. While safe, this bounds productivity to the human's immediate typing speed.

When teams remove the human from the inner loop to achieve autonomous execution, three predictable failure modes emerge:

1. **Circular Dependency Ping-Pong**: When resolving complex architectural errors (such as circular imports in Python), a worker agent without cycle memory edits Module A, which breaks Module B; it then edits Module B, which re-breaks Module A. Left unconstrained, the agent oscillates until it exhausts its token budget or hard turn cap.
2. **Confirmation Bias & Self-Grading Sycophancy**: Language models suffer from psychological confirmation bias when evaluating their own code. When a model that wrote a flawed patch is asked *"Did you verify that this handles all edge cases?"*, its internal attention patterns strongly bias it toward answering *"Yes, the logic is sound and all constraints are satisfied."*
3. **Runaway Cost Velocity**: Without explicit rate governors, an agent caught in a rapid tool loop can dispatch hundreds of API calls in minutes, accumulating hundreds of dollars in provider invoices on fruitless retries.

The supervisor harness solves these challenges by implementing an outer control plane with deterministic circuit breakers, token velocity limits, and a strict Maker-Checker architectural separation.

## Anthropic's Multi-Agent Supervisor Triad

When a single model acts as both author and auditor of its own code, confirmation bias leads to blindness: the model believes its code is correct because it wrote it.

Anthropic's long-running agent research formalizes the **Supervisor Triad**:

<AnthropicSupervisorTriadVisualizer />

The triad divides responsibilities across three distinct, isolated roles:

1. **The Planner**: Receives the user goal, inspects the repository map (`AGENTS.md`), and decomposes the goal into a sequential checklist written to `feature_list.json`. The Planner never writes production code.
2. **The Generator (Worker)**: Operates inside the execution sandbox. It picks the current checklist item, reads relevant files, and modifies code. It runs until it believes the task is complete.
3. **The Evaluator (Checker)**: Spun up with a completely fresh, unpolluted context window. It receives only the unified `git diff` generated by the worker and the requirement specification. It executes the 3-layer verification engine independently. If verification passes, it commits the changes; if it fails, it injects an XML diagnostic envelope back into the Generator.

<GoDeeper title="Go deeper: Why Maker-Checker separation eliminates Confirmation Bias in AI">

In psychology and agentic systems, **Confirmation Bias** describes how an agent evaluates its own output. When the Generator agent writes a function, its internal attention heads are biased toward the prompt path that led to that implementation. If you prompt it *"Did you make any errors?"*, it reliably hallucinates *"No, the logic is sound."*

By instantiating a completely separate **Evaluator Agent** with a fresh context window containing only the file diff and the requirements in `AGENTS.md`, the Evaluator examines the patch with zero preconceptions or sycophancy, catching edge cases the Generator missed.

</GoDeeper>

## Production Supervisor Loop Configuration

In production harnesses, the supervisor enforces hard operating constraints via environment variables or a YAML configuration:

```yaml
# supervisor_policy.yaml - Production Autonomous Loop Guardrails
supervisor:
  # Hard ceilings to prevent runaway processes
  max_iterations_per_task: 15
  global_timeout_seconds: 1800 # 30 minutes max
  max_budget_usd: 2.50

  # Velocity governors (leaky bucket rate limiting)
  token_velocity:
    max_input_tokens_per_hour: 500000
    max_output_tokens_per_hour: 40000
    cooldown_on_exhaustion_sec: 120

  # Circuit breaker thresholds
  cycle_detector:
    hash_algorithm: "sha256"
    repetition_threshold: 2 # Trip if identical state hash observed twice
    action_on_trip: "halt_and_reprompt_architectural_refactor"

  # Process sandbox limits
  sandbox:
    memory_limit_mb: 2048
    max_subprocesses: 64
    network_egress: false
```

## A Full Worked Example: State Fingerprinting & Circuit Breakers

Consider an agent attempting to resolve a circular dependency between `router.py` and `handler.py`. The agent generates three sequential turns:

1. **Turn 1**: Modifies `router.py` with `import handler`. The Python interpreter raises `ImportError: cannot import name router from partially initialized module`. The harness fingerprints this state to hash `[fc207e10]`.
2. **Turn 2**: Modifies `handler.py` with `import router`. The interpreter raises `ImportError: cannot import name handler from partially initialized module`. State hash is `[bfd76fa9]`.
3. **Turn 3**: Reverts `handler.py` and re-attempts `router.py` with `import handler`. State hash calculates to `[fc207e10]`.

Because hash `[fc207e10]` has now been observed **2 times** (matching the repetition threshold), the circuit breaker trips immediately. It halts the loop before Turn 4 can execute, preventing 12 additional wasted turns.

```
       Turn 1: router.py  ──> State Hash [fc207e10] (Count: 1)
                                      │
       Turn 2: handler.py ──> State Hash [bfd76fa9] (Count: 1)
                                      │
       Turn 3: router.py  ──> State Hash [fc207e10] (Count: 2)
                                      │
                                      ▼
             [ CIRCUIT BREAKER TRIPPED: REPETITION DETECTED ]
             • Action: Halt execution loop
             • Strategy: Flush turn history, inject architectural refactor prompt
```

<RunnableCode code={`import hashlib
from typing import List, Dict, Any

class CycleDetector:
    """Detects oscillation cycles in autonomous agent execution loops."""

    def __init__(self, repeat_threshold: int = 2):
        self.history: List[str] = []
        self.threshold = repeat_threshold

    def record_and_check(self, edited_file: str, diff_text: str, error_msg: str) -> bool:
        # Generate deterministic fingerprint of turn state
        payload = f"{edited_file}:{diff_text}:{error_msg}"
        turn_hash = hashlib.sha256(payload.encode()).hexdigest()[:8]
        
        self.history.append(turn_hash)
        occurrences = self.history.count(turn_hash)
        
        print(f"Turn {len(self.history)}: State Hash=[{turn_hash}] (Observed {occurrences} time(s))")
        if occurrences >= self.threshold:
            print("  >>> CIRCUIT BREAKER TRIGGERED: Agent is oscillating in an infinite loop! <<<")
            return True # Tripped!
        return False

detector = CycleDetector(repeat_threshold=2)

# Simulated Agent Turns (Ping-Pong oscillation between router.py and handler.py)
simulated_turns = [
    {"file": "router.py", "diff": "import handler", "err": "ImportError: cannot import name router from partially initialized module"},
    {"file": "handler.py", "diff": "import router", "err": "ImportError: cannot import name handler from partially initialized module"},
    {"file": "router.py", "diff": "import handler", "err": "ImportError: cannot import name router from partially initialized module"},
]

print("=== Autonomous Loop Cycle Detector Verification ===\\n")
for t in simulated_turns:
    tripped = detector.record_and_check(t["file"], t["diff"], t["err"])
    if tripped:
        print("Harness Action: Halting loop, injecting architectural refactor prompt into agent context.\\n")
        break

## Background Entropy & Garbage Collection Agents

In large autonomous deployments, agents write code rapidly but introduce subtle code decay over dozens of iterations: orphaned imports, stale comments, unused helper functions, and misaligned indentation.

To counter this decay, OpenAI's production engineering methodology introduces asynchronous **Entropy Collection Agents**:

<OpenAIEntropyVisualizer />

Entropy agents run outside the critical user path:
- **Dead Code Scavengers**: Periodically run `vulture` or `deadcode` to purge unreferenced functions created during exploratory debugging turns.
- **Import Consolidators**: Run `ruff check --select I --fix` to organize module imports alphabetically and eliminate duplicate bindings.
- **Documentation Re-synchronizers**: Compare docstring parameters against actual function AST signatures to ensure parameter names match reality.

## Common Problems & Fixes

1. **Deadlock from Strict Evaluator Rejections**: The Generator and Evaluator get into a permanent disagreement: Generator believes its patch satisfies requirements, but Evaluator repeatedly rejects with minor formatting nitpicks.
   - *Fix*: Implement an **Escalation Arbiter**: if Evaluator rejects 3 times on formatting or non-functional criteria, the harness runs automated formatters (`ruff format`) and escalates to human review.
2. **Context Bloat inside the Supervisor**: The supervisor process accumulates all historical worker traces, becoming slow and expensive.
   - *Fix*: Keep the supervisor completely stateless. Pass only the unified git diff and structured test status to the supervisor on each turn.
3. **Premature Halting from False-Positive Cycle Hits**: An agent legitimately re-touches a file to add a new function, but the error message from an unrelated test matches earlier output.
   - *Fix*: Include the git unified diff (`diff_text`) in the SHA256 hash payload. Two turns on the same file with different code diffs produce distinct fingerprints.

<NotebookCallout color="amber" title="Supervisor Golden Rule">
An agent should never judge its own work. Always enforce the Maker-Checker separation: the Generator proposes patches inside the sandbox, while an independent Evaluator verifies deterministic proofs and signs off on git commits.
</NotebookCallout>

## When *Not* to Use It

| Situation | Better Choice | Why |
| :--- | :--- | :--- |
| Single-turn code translation or linting | Direct single-pass LLM call | Static conversions have no intermediate state; multi-agent loops add latency and token overhead. |
| Time-critical user request (< 3 seconds) | Synchronous endpoint | Autonomous multi-agent loops require multiple turns and minutes to execute. |
| Production hotfix on mission-critical database | Human engineer with manual review | High-risk infrastructure changes should not be delegated to unattended autonomous loops. |

## Remember

| Idea | Core Rule |
| :--- | :--- |
| **Maker-Checker** | Decouple code generation from evaluation; use fresh contexts for auditing. |
| **Circuit Breakers** | Fingerprint turns with SHA256 hashes to halt circular ping-pong loops. |
| **Token Velocity** | Enforce hourly token consumption ceilings to prevent runaway billing. |
| **Entropy Collectors**| Run asynchronous background agents to sweep dead code and stale imports. |
| **Structured Halting**| Halt on repeat hashes, budget exhaustion, or 100% verification pass. |
