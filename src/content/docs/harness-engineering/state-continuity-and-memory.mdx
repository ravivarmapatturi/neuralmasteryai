# State, Continuity & Memory Compaction

A typical production engineering task requires 15 to 40 distinct tool invocations across multiple hours. If an agent process crashes, restarts, or switches context, how does it know what was already done and what remains?

In naked model architectures, a restarted session begins with total amnesia. The agent inspects files it already edited, re-implements already finished modules, or accidentally reverts its own work.

<ELI5>

Imagine working on a multi-day construction project. If you wake up every morning with total memory loss and have to guess what was built by wandering around the site, you'll end up tearing down finished walls and forgetting the plumbing.

Instead, the foreman leaves a waterproof clipboard on the job site: a checklist of completed rooms, pending tasks, and architectural blueprints (`feature_list.json`). No matter who starts the shift, they check the clipboard and get straight to work.

</ELI5>

## Why This Exists

Autonomous software engineering tasks differ fundamentally from single-turn chat completions. A typical feature implementation touches multiple files, runs compilers, executes test suites, and iterates through error traces.

When an autonomous agent runs over dozens of turns without explicit state architecture, two catastrophic failure modes emerge:

1. **Semantic Amnesia & Compaction Drift**: When context windows fill up, naive agent frameworks invoke a secondary model to "summarize past conversation." Research demonstrates that conversational summaries suffer from lossy compression: line numbers disappear, subtle architectural constraints get dropped, and intent gets conflated with completion. The agent begins re-running tests it already resolved or modifying working code.
2. **Crash Fragility & Orphaned Modularity**: In real cloud deployments, agent processes terminate unexpectedly due to container preemption, host spot-instance eviction, or transient API timeouts. If task state exists purely in volatile process RAM or model context, the entire run must be aborted and restarted from scratch, burning developer hours and API spend.

Production harness architectures resolve this by treating the host filesystem as the ground truth of system state, using **externalized state artifacts** paired with **two-pass token compaction**.

## Anthropic's State-Externalization Pattern: `feature_list.json`

In Anthropic's research on long-running application development, agents that rely on conversational memory inevitably suffer from **amnesia** or **context anxiety**.

The solution is the **State-Externalization Pattern**: keeping task state outside the volatile LLM context window in structured on-disk files.

<GoDeeper title="Go deeper: Why conversational summaries are inferior to deterministic state artifacts">

When an agent loop compacts memory, naive frameworks invoke a summarizer LLM: *"Summarize the past 15 turns in 2 paragraphs."*

This introduces three critical failure modes:
1. **Hallucinated Progress**: The summarizer often assumes an intent to fix a bug means the bug was actually fixed.
2. **Context Bleed**: Error tracebacks disappear into vague statements like *"We fixed an index error"*, losing the exact line number.
3. **Cumulative Drift**: Over 50 turns, each summary summarizes the previous summary, creating a game of telephone where original user constraints are completely erased.

By keeping `feature_list.json` on disk, the state remains deterministic, machine-readable, and immune to summarization drift.

</GoDeeper>

### Atomic Disk Serialization

Because autonomous agents can be terminated mid-execution, writing directly to `feature_list.json` with standard file handles risks creating truncated, unparseable JSON files. Production harnesses enforce **atomic writes**:

```python
import json
import os
import tempfile
from typing import Any, Dict

def atomic_write_json(file_path: str, data: Dict[str, Any]) -> None:
    """Writes JSON data atomically using a temporary file and atomic rename."""
    directory = os.path.dirname(os.path.abspath(file_path))
    with tempfile.NamedTemporaryFile("w", dir=directory, delete=False, suffix=".tmp") as tf:
        json.dump(data, tf, indent=2)
        tf.flush()
        os.fsync(tf.fileno())
        temp_name = tf.name
    # POSIX atomic rename: replaces target file instantaneously
    os.replace(temp_name, file_path)
```

### Git Worktrees and Checkpoint Rollback

When an autonomous agent implements a multi-step feature, changes can introduce subtle bugs that break unrelated subsystems. If the agent operates directly on the main working tree, rolling back failed attempts requires messy interactive git commands that models often mishandle.

Production harnesses isolate each checklist task inside a dedicated **Git Worktree**:

```bash
# Production harness worktree isolation workflow
# 1. Create a clean isolated worktree for the specific checklist item
git worktree add -b agent/task-flash-kernel ../worktrees/task-flash main

# 2. Agent executes all edits and test runs inside the isolated directory
cd ../worktrees/task-flash

# 3. If tests pass, commit and merge back to main
git commit -am "feat(attention): implement flash attention kernel"
cd /workspace/repo
git merge --ff-only agent/task-flash-kernel
git worktree remove ../worktrees/task-flash

# 4. If the agent fails or enters an unrecoverable loop, prune the worktree instantly
git worktree remove --force ../worktrees/task-flash
git branch -D agent/task-flash-kernel
```

This isolation ensures that failed agent experiments leave zero residual artifacts in the primary codebase, and resetting state requires a single filesystem unlink rather than complex git reconciliations.

## A Full Worked Example: Two-Pass History Compaction

Consider an agent running a test-fix cycle. Its raw conversational history contains 551 tokens across 6 turns, dominated by 400+ tokens of verbose compiler and pytest logs.

The target context budget for conversation history is **150 tokens**.

### Run It Yourself

Execute this self-contained Python implementation of the two-pass compaction engine. Notice how historical test failures and verbose assertion outputs are compacted into semantic markers without losing user intent:

<RunnableCode code={`import json
from dataclasses import dataclass
from typing import List

@dataclass
class Message:
    role: str
    content: str
    is_tool_trace: bool = False

def estimate_tokens(text: str) -> int:
    # Standard heuristic: 4 characters per token
    return max(1, len(text) // 4)

def compact_conversation(messages: List[Message], budget_tokens: int = 150) -> List[Message]:
    total_tokens = sum(estimate_tokens(m.content) for m in messages)
    print(f"Initial Token Count: {total_tokens} tokens (Target Budget: {budget_tokens})")
    
    if total_tokens <= budget_tokens:
        return messages

    # Pass 1: Collapse older tool outputs (> 2 turns old)
    compacted: List[Message] = []
    recent_cutoff = len(messages) - 2

    for i, msg in enumerate(messages):
        if i > 0 and i < recent_cutoff and msg.is_tool_trace:
            compacted.append(Message(
                role=msg.role,
                content="[Historical tool trace pruned: FAILED test_3 (AttributeError)]",
                is_tool_trace=True
            ))
        else:
            compacted.append(msg)

    # Pass 2: If still exceeding budget, summarize verbose recent tool logs
    cur_tokens = sum(estimate_tokens(m.content) for m in compacted)
    if cur_tokens > budget_tokens:
        second_pass = []
        for msg in compacted:
            if msg.is_tool_trace and len(msg.content) > 100:
                second_pass.append(Message(
                    role=msg.role,
                    content="[Recent tool trace: 3 passed in 1.4s (100%)]",
                    is_tool_trace=True
                ))
            else:
                second_pass.append(msg)
        compacted = second_pass

    new_total = sum(estimate_tokens(m.content) for m in compacted)
    saved = total_tokens - new_total
    print(f"Compacted Token Count: {new_total} tokens -> Saved {saved} tokens ({saved / total_tokens * 100:.1f}% reduction)\\n")
    return compacted

# Simulate 6 turns of interactive debugging with verbose pytest output
history = [
    Message("system", "You are an autonomous Python harness agent working on feature_list.json"),
    Message("user", "Run the test suite and fix test_attention.py"),
    Message("tool", "PASSED test_1\\nPASSED test_2\\nFAILED test_3 (AttributeError: 'NoneType' object has no attribute 'dim')\\n" * 15, is_tool_trace=True),
    Message("agent", "I found the NoneType bug in forward(); patching line 42 now."),
    Message("tool", "PASSED test_1\\nPASSED test_2\\nPASSED test_3\\n[100% passed in 1.4s]\\n" * 10, is_tool_trace=True),
    Message("agent", "All tests now pass. Updating feature_list.json.")
]

compacted_history = compact_conversation(history, budget_tokens=150)
for m in compacted_history:
    print(f"[{m.role.upper()}]: {m.content[:75]}...")

## Common Problems & Fixes

1. **State Desynchronization with Git**: An agent updates `feature_list.json` to mark a feature "passed", but fails to stage or commit the matching Python files.
   - *Fix*: The harness links state transitions to git commits. A task in `feature_list.json` cannot transition to `passed` unless the working directory has a clean git status and matching commit hash.
2. **Context Bleed Across Switched Tasks**: When an agent finishes Task A and begins Task B, residual tool traces from Task A confuse tool selection.
   - *Fix*: Flush working memory between checklist items. When Task A passes verification, wipe conversation turns except for the root system prompt, the updated `feature_list.json`, and Task B's requirements.
3. **Corrupted State Files from Mid-Flight SIGKILL**: Cloud preemptions leave half-written JSON files on disk.
   - *Fix*: Always write to a temporary file in the same filesystem directory and execute an atomic `os.replace()`.

<NotebookCallout color="cobalt" title="State Persistence Principle">
Treat the filesystem as the source of truth, not the context window. Always write task status to `feature_list.json` and human milestones to `progress.txt`. When context is cleared or refreshed, reloading these two files restores full autonomous momentum.
</NotebookCallout>

## When *Not* to Use It

| Situation | Better Choice | Why |
| :--- | :--- | :--- |
| Single-turn ad-hoc CLI query (`explain this regex`) | Pure stateless completion | No tools or multi-file edits are performed; state files add unnecessary filesystem clutter. |
| Deterministic batch migrations across 500 files | Scripted AST codemod (LibCST) | A deterministic AST script executes in seconds with zero token cost; an agent loop is slow and non-deterministic. |
| Ephemeral question-answering over documentation | In-memory RAG pipeline | Document QA does not mutate repository state; persisting task checklists is unnecessary. |

## Remember

| Idea | Core Rule |
| :--- | :--- |
| **Ground Truth** | The filesystem is the source of truth; volatile LLM context is transient. |
| **feature_list.json** | Use a structured checklist with deterministic test hashes to track task state. |
| **Two-Pass Compaction** | Collapse historical tool logs first; truncate recent logs only if budget requires. |
| **Atomic Writes** | Always write state files via `tempfile` and `os.replace` to prevent corrupted state. |
| **Task Boundary Flushes**| Flush conversation memory when transitioning between independent checklist tasks. |
