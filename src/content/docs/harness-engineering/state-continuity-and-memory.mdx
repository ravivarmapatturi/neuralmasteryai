# State, Continuity & Memory Compaction

A typical production engineering task requires 15 to 40 distinct tool invocations across multiple hours. If an agent process crashes, restarts, or switches context, how does it know what was already done and what remains?

In naked model architectures, a restarted session begins with total amnesia. The agent inspects files it already edited, re-implements already finished modules, or accidentally reverts its own work.

<ELI5>

Imagine working on a multi-day construction project. If you wake up every morning with total memory loss and have to guess what was built by wandering around the site, you'll end up tearing down finished walls and forgetting the plumbing.

Instead, the foreman leaves a waterproof clipboard on the job site: a checklist of completed rooms, pending tasks, and architectural blueprints (`feature_list.json`). No matter who starts the shift, they check the clipboard and get straight to work.

</ELI5>

## 2. Anthropic's State-Externalization Pattern: `feature_list.json`

In Anthropic's research on long-running application development, agents that rely on conversational memory inevitably suffer from **amnesia** or **context anxiety**.

The solution is the **State-Externalization Pattern**: keeping task state outside the volatile LLM context window in structured on-disk files.

<GoDeeper title="Go deeper: Why conversational summaries are inferior to deterministic state artifacts">

When an agent loop compacts memory, naive frameworks invoke a summarizer LLM: *"Summarize the past 15 turns in 2 paragraphs."*

This introduces three critical failure modes:
1. **Hallucinated Progress**: The summarizer often assumes an intent to fix a bug means the bug was actually fixed.
2. **Context Bleed**: Error tracebacks disappear into vague statements like *"We fixed an index error"*, losing the exact line number.
3. **Cumulative Drift**: Over 50 turns, each summary summarizes the previous summary, creating a game of telephone where original user constraints are completely erased.

By keeping `feature_list.json` on disk, the state remains deterministic, machine-readable, and immune to summarization drift.

</GoDeeper>

## 3. Python Compaction Algorithm: Live Interactive Runner

Below is a production compaction engine in Python. Run this live in-browser demo to see how old, verbose tool outputs are pruned while keeping recent turns and state checklists completely intact:

<RunnableCode code={`from dataclasses import dataclass
from typing import List

@dataclass
class Message:
    role: str
    content: str
    is_tool_trace: bool = False

def estimate_tokens(text: str) -> int:
    # Approximate rule of thumb: ~4 characters per token
    return max(1, len(text) // 4)

def compact_conversation(messages: List[Message], budget_tokens: int = 150) -> List[Message]:
    total_tokens = sum(estimate_tokens(m.content) for m in messages)
    print(f"Initial Token Count: {total_tokens} tokens (Budget: {budget_tokens})")
    
    if total_tokens <= budget_tokens:
        return messages

    # Compaction Strategy:
    # 1. Keep the initial system instruction (turn 0)
    # 2. Keep the last 2 turns intact
    # 3. Collapse old tool outputs in between into compact semantic markers
    compacted: List[Message] = []
    recent_cutoff = len(messages) - 2

    for i, msg in enumerate(messages):
        if i > 0 and i < recent_cutoff and msg.is_tool_trace:
            # Prune noisy 500-token tool logs into a 5-token marker
            compacted.append(Message(
                role=msg.role,
                content="[Tool log pruned: verified pass by pytest]",
                is_tool_trace=True
            ))
        else:
            compacted.append(msg)

    new_total = sum(estimate_tokens(m.content) for m in compacted)
    print(f"Compacted Token Count: {new_total} tokens -> Saved {total_tokens - new_total} tokens!\\n")
    return compacted

# Simulate an agent conversation with verbose test outputs
history = [
    Message("system", "You are an autonomous Python harness agent working on feature_list.json"),
    Message("user", "Run the test suite and fix test_attention.py"),
    Message("tool", "PASSED test_1\\nPASSED test_2\\nFAILED test_3 (AttributeError: 'NoneType' object has no attribute 'dim')\\n" * 15, is_tool_trace=True),
    Message("agent", "I found the NoneType bug in forward(); patching line 42 now."),
    Message("tool", "PASSED test_1\\nPASSED test_2\\nPASSED test_3\\n[100% passed in 1.4s]\\n" * 10, is_tool_trace=True),
    Message("agent", "All tests now pass. Updating feature_list.json.")
]

compacted_history = compact_conversation(history, budget_tokens=150)
for m in compacted_history:
    print(f"[{m.role.upper()}]: {m.content[:75]}...")
`} />

<NotebookCallout color="blue" title="State Persistence Principle">
**Treat the filesystem as the source of truth, not the context window.** Always write task status to `feature_list.json` and human milestones to `progress.txt`. When context is cleared or refreshed, reloading these two files restores full autonomous momentum.
</NotebookCallout>
