# Coordination and Distributed Workflows

<ELI5>Several workers need rules for who may decide, which state is committed, and how unfinished actions recover. More processes do not establish those rules automatically. These chapters follow authority and failure through concrete examples.</ELI5>

## Why it exists

Multiple processes can fail independently, pause, or lose contact while clients still send work. A timeout does not reveal whether a remote operation committed. These pages build explicit rules for shared authority, partial completion, and recovery.

## Common mistakes

| Mistake | Why it happens | Fix |
| :--- | :--- | :--- |
| Treating every storage or coordination choice as one decision | Different mechanisms protect different boundaries | Trace one operation across ownership, reads, writes, and failure |
| Reading a chapter list without applying it | Terms stay abstract without a concrete operation | Use one case study and record its invariant and recovery path |
