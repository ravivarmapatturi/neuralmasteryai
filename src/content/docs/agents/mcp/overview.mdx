## 1. What is Model Context Protocol?

### Visual Architecture Story: Without MCP vs. With MCP
Toggle between custom glue-code mesh and the universal USB-C MCP standard:

<McpHeroStoryVisual />

### The Core Problem & Solution
Large Language Models (LLMs) are extraordinarily capable at reasoning and writing code, but are inherently isolated by static training cutoffs and lack direct access to real-time databases or APIs.

MCP bridges this gap by providing an open **JSON-RPC 2.0** messaging standard between AI applications and external software services.

### MCP Doesn't Replace APIs — It Standardizes How LLMs Discover and Call Them

A common misconception: MCP is not a competitor to APIs, and it doesn't remove the need for them. An MCP server almost always calls a real API (or database, or filesystem) under the hood to actually do the work — MCP is the standardized *discovery-and-invocation layer* sitting on top, so an LLM can find out what's available and call it consistently, instead of a developer hand-writing bespoke integration code for every service's unique API shape.

| | **API** | **MCP** |
| :--- | :--- | :--- |
| **Purpose** | Direct, predefined access to a specific service. | A standard for LLMs to discover and use tools and resources from external systems. |
| **Interface** | Fixed endpoints (REST, GraphQL, ...). | Standardized protocol (JSON-RPC 2.0). |
| **Scope** | One API per service. | Many tools and resources reachable via one server. |
| **Discovery** | Client must already know what to call and how. | LLM lists available tools at runtime and decides which to use. |
| **Context** | Stateless, request–response. | Stateful, tool-aware — supports richer context (files, code, DB schemas). |
| **Example** | `GET /weather?city=Kolkata` → returns weather data. | "List my recent files" → MCP discovers and calls the file tool, returns the result to the LLM. |

**In short:** an API gives you access to *one* service. MCP gives an LLM a standardized way to find and use *many* services — and it needs real APIs underneath every one of those services to actually call. Two things still only make sense as plain APIs, never MCP: non-AI clients (a mobile app calling a weather service directly has no LLM in the loop to benefit from MCP's discovery layer), and the underlying service implementation itself (someone still has to build the API an MCP server wraps).

## 3. Key Concepts & Core Terminology

<ClientServerRolesDiagram />

### The 3 Architectural Entities

1. **Host**: The user-facing AI application end-users interact with directly (Claude Desktop, Cursor IDE, custom python script).
2. **Client**: A component running inside the Host application that maintains a dedicated 1:1 connection with a specific MCP Server.
3. **Server**: An external process or remote web service exposing capabilities (Tools, Resources, Prompts) via the MCP standard format.

| Capability | Control & Trigger | Description | Real-World Example |
| :--- | :--- | :--- | :--- |
| **Tools** | Invoked by LLM (with user consent) | Executable functions that perform computational actions or retrieve dynamic data. | `execute_python_code`, `query_postgres_db`, `post_slack_message`. |
| **Resources** | Read-only pulled by Host | Passive data feeds (files, schemas, logs) exposed via URI schemes (`file://`, `postgres://`). | `file:///project/src/main.py`, `postgres://analytics/users_table`. |
| **Prompts** | Triggered by User / Host | Pre-defined templates or workflows guiding model-user interactions. | `code_review_style`, `generate_postmortem_template`. |
| **Sampling** | Server $\rightarrow$ Host request | Server-initiated requests asking the Host's LLM to generate completions for recursive evaluation. | Server asks Host LLM to review generated code before returning result. |

### FastMCP Python Example

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Analytics Server")

@mcp.tool()
def analyze_sentiment(text: str) -> dict:
    """Analyzes text sentiment polarity and returns structured assessment."""
    text_lower = text.lower()
    score = 0.8 if "great" in text_lower or "love" in text_lower else -0.8 if "bad" in text_lower else 0.0
    return {"text": text, "score": score, "assessment": "positive" if score > 0 else "neutral"}

if __name__ == "__main__":
    mcp.run(transport="stdio")
```

## 10. Step-by-Step Guide: How to Build an MCP Client

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    server_params = StdioServerParameters(command="python", args=["server.py"])
    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()
            result = await session.call_tool("analyze_sentiment", arguments={"text": "Neural Mastery is awesome!"})
            print(result.content[0].text)

if __name__ == "__main__":
    asyncio.run(main())
```
