# CS Fundamentals for AI Engineers — Roadmap

<ELI5>

AI engineers need enough systems fluency to run training and serving workloads, diagnose failures, and communicate across software boundaries. This roadmap orders the practical topics so each chapter builds on the previous one.

</ELI5>

## 1. [Operating Systems & Concurrency](/docs/cs-fundamentals/operating-systems-and-concurrency)
- [x] Processes vs. threads, the process/thread memory model
- [x] Concurrency vs. parallelism — the distinction that matters for Python specifically
- [x] The GIL, multiprocessing vs. multithreading for ML workloads
- [x] Memory: stack vs. heap, virtual memory, paging
- [x] CPU caches (L1/L2/L3) and cache-friendly data access
- [x] File systems and I/O basics

## 2. [Networking & Distributed Systems](/docs/cs-fundamentals/networking-and-distributed-systems)
- [x] HTTP request/response, status codes, REST basics
- [x] TCP/IP vs. UDP, sockets, latency vs. bandwidth
- [x] DNS resolution
- [x] Load balancing strategies
- [x] CAP theorem, consensus (Raft/Paxos intuition)
- [x] Why distributed training and distributed serving are genuinely hard: partial failure, network partitions, stragglers

## 3. [APIs, HTTP & Communication Patterns](/docs/cs-fundamentals/apis-http-and-protocols)
- [x] HTTP methods, idempotency, status code families
- [x] REST vs. RPC-style vs. GraphQL
- [x] Authentication vs. authorization, API keys, OAuth 2.0, JWTs
- [x] Polling (short/long), webhooks, Server-Sent Events, WebSockets — when to use which
- [x] FastAPI: path operations, Pydantic models, dependency injection, async endpoints

## 4. [Linux, Git & Developer Tooling](/docs/cs-fundamentals/linux-git-and-tooling)
- [x] The shell: pipes, redirection, `grep`/`awk`/`sed`, process management
- [x] The Linux filesystem and permissions model
- [x] Git internals: objects, commits, trees, blobs — not just commands
- [x] Compilers vs. interpreters, what "compiled" actually means for Python/PyTorch

## 5. [Software Engineering Practice](/docs/cs-fundamentals/software-engineering-practices)
- [x] Design patterns relevant to ML systems (not a full GoF tour)
- [x] Testing philosophy: what to test, what not to test
- [x] Profiling: CPU profiling, memory profiling, finding the actual bottleneck
- [x] Debugging methodology: bisection, reproducing, isolating

## Common mistakes

| Mistake | Why it happens | Fix |
| --- | --- | --- |
| Skipping foundations | A model can be correct while its service fails | Follow the chapter order and connect concepts to system tasks |
| Reading definitions only | Terms are hard to apply without operational context | Run the examples in linked chapters |
| Treating the roadmap as a checklist | Roles need different depth | Prioritize the systems your work depends on |

## When not to use it

| Situation | Better choice |
| --- | --- |
| You need model theory | Use the Machine Learning roadmap |
| You need deployment practice | Continue to MLOps after the systems foundations |
