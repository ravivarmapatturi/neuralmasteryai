# Agent Protocols Atlas

An agent calling a tool looks new, but much of it is old. A generated stub from 1984, a JSON message, a schema and an OAuth token are all still in that call. What is new is who decides to make it: a model, working from a description, at runtime. This atlas follows that story in date order, so you can see which problem each layer solved.

<ELI5>

Think of an office. A remote call is phoning a colleague. REST is an agreed way of asking the records room for a file. OAuth is a visitor badge that opens only certain doors. Function calling is a new assistant who writes down which call should be made, while you still make it. MCP is a standard socket, so any assistant can use any office equipment. A2A is how assistants from different companies hand work to each other.

</ELI5>

## The Layers Still Stack

These entries did not replace each other. A single MCP tool call can use a schema to describe the tool, JSON-RPC for the message, HTTP to carry it, OAuth to authorize it, and a REST API behind the server. When a call fails, work through those layers one at a time.

Protocols in the last era are still changing, so check the current specification before you build on the details here.
