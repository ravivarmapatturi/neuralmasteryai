# Speech & Audio Tasks

<ELI5>

There are a handful of jobs we give a computer that listens. Write down what was said. Say this text out loud. Tell me who is speaking. Tell me who spoke when in this meeting. Remove the traffic noise from this call. Each job starts from the same chart of sound over time, and each one needs its own way of turning that chart into an answer.

</ELI5>

## Why This Exists

[Audio Fundamentals](/docs/speech-audio/audio-fundamentals) turned a waveform into a log-mel spectrogram: about 100 frames per second, each a vector of 80 numbers. Every task on this page starts there and reuses the sequence-modelling and attention machinery from [Deep Learning](/docs/deep-learning/roadmap). What differs is the shape of the output. Speech recognition must turn 100 frames per second into a few words per second without knowing which frames belong to which word. Synthesis runs the other way and must invent detail the text does not contain. Verification must turn a whole clip into one point in an embedding space. Most of the engineering is about those mismatches, and about measuring the result correctly.

## ASR: Automatic Speech Recognition

ASR converts speech to text. The core problem is **alignment**: a 2-second clip is 200 frames but "turn the lights off" is 4 words, and training data rarely says which frames belong to which letter. There are three main designs:

- **CTC** (connectionist temporal classification) lets the model emit one symbol per frame, including a special **blank**, and defines the output as what remains after merging repeated symbols and removing blanks. The CTC loss sums the probability of every frame-level path that collapses to the target text, so training needs only the transcript, not an alignment.
- **Encoder-decoder with attention** encodes the whole clip, then generates text tokens one at a time while attending back over the encoded frames, the same pattern as [machine translation](/docs/nlp/nlp-task-taxonomy#machine-translation).
- **Transducers** (RNN-T) combine the two: they emit tokens frame by frame like CTC, but each prediction also conditions on the tokens already emitted. They are the usual choice for on-device streaming recognition.

**Whisper** is an encoder-decoder transformer trained on 680,000 hours of audio paired with transcripts gathered from the web: weakly labelled, but vast. As with LLM pretraining, scale and diversity bought robustness. Whisper works across accents, noise and nearly 100 languages without task-specific fine-tuning.

### A Full Worked Example: CTC Collapse and Word Error Rate

Suppose the per-frame best symbols are `hh_ell_loo_`. Merging repeats gives `h_el_lo_`, and dropping blanks gives `hello`. The blank between the two l's matters: without it, `ll` merges into one `l` and the output is `helo`. The blank is the only way CTC can produce a doubled letter.

ASR is scored by **word error rate** (WER): the word-level edit distance (substitutions, deletions and insertions) between hypothesis and reference, divided by the number of reference words. Against "turn the kitchen lights off" (5 words), "turn the kitchen light off" has one substitution, WER 0.20. "turn kitchen lights of" has a deletion and a substitution, WER 0.40.

<RunnableCode code={`# Greedy CTC output: best symbol per frame, then merge repeats and drop blanks
BLANK = "_"
frames = ["h", "h", "_", "e", "l", "l", "_", "l", "o", "o", "_"]

def ctc_collapse(seq):
    out, prev = [], None
    for s in seq:
        if s != prev and s != BLANK:
            out.append(s)
        prev = s
    return "".join(out)

print("frames :", "".join(frames))
print("decoded:", ctc_collapse(frames))      # the blank between the l's keeps "ll"

# Word error rate: word-level edit distance / reference length
def wer(ref, hyp):
    r, h = ref.split(), hyp.split()
    d = [[0] * (len(h) + 1) for _ in range(len(r) + 1)]
    for i in range(len(r) + 1):
        d[i][0] = i
    for j in range(len(h) + 1):
        d[0][j] = j
    for i in range(1, len(r) + 1):
        for j in range(1, len(h) + 1):
            sub = d[i-1][j-1] + (r[i-1] != h[j-1])
            d[i][j] = min(sub, d[i-1][j] + 1, d[i][j-1] + 1)
    return d[-1][-1] / len(r)

ref = "turn the kitchen lights off"
for hyp in ["turn the kitchen lights off",
            "turn the kitchen light off",
            "turn kitchen lights of",
            "um so turn the uh kitchen lights off please now"]:
    print(f"WER {wer(ref, hyp):.2f}  {hyp!r}")

# Try it: remove the "_" between the two l's in frames. CTC merges them and
# decodes "helo": a blank is the only way to emit a doubled letter.`} />

"Turn off the lights." and "turn off the lights" differ by case and punctuation, and "10" versus "ten" is a substitution. Published Whisper numbers use a text normaliser for this reason. Apply the same normaliser to both sides, or WER measures formatting instead of recognition.
</NotebookCallout>

<GoDeeper title="Go deeper: how the CTC loss sums over every alignment">

The number of frame-level paths that collapse to a given text grows combinatorially with the number of frames, so CTC cannot list them. It uses dynamic programming instead. Insert blanks between and around the target letters (so "cat" becomes `_c_a_t_`), and build a table whose entry $\alpha_t(s)$ is the total probability of all paths that have emitted the first $s$ symbols of that extended sequence after $t$ frames. Each entry comes from at most three predecessors: stay on the same symbol, move on by one, or skip a blank between two different letters. The loss is the negative log of the total at the last frame, computed in $O(T \cdot S)$ time, the same forward-algorithm idea as the HMM in [Classical NLP](/docs/nlp/classical-nlp). CTC assumes frames are conditionally independent given the audio, which is why CTC models benefit from an external language model at decoding time.

</GoDeeper>

## TTS: Text-to-Speech

TTS turns text into audio. The classic pipeline has two stages:

- **An acoustic model** maps text, usually converted to phonemes first, to a mel spectrogram: what the text should sound like, but not yet playable audio. Tacotron 2 and FastSpeech 2 are standard examples.
- **A vocoder** turns the mel spectrogram into a waveform. This is hard on its own, because the spectrogram discards phase. WaveNet solved it with high quality but slowly; GAN vocoders such as HiFi-GAN are fast enough for real time.

End-to-end models (VITS) learn both stages jointly, and newer systems treat speech as discrete tokens from a neural audio codec and generate them with a language model or with diffusion (see [Generative Models](/docs/deep-learning/generative-models)). **Voice cloning** conditions the model on a speaker embedding computed from a short reference clip, so a new voice needs seconds of audio rather than a new model.

<TtsPipelineDiagram />

TTS quality is usually reported as a mean opinion score (MOS): listeners rate naturalness from 1 to 5. Intelligibility can be checked automatically by running ASR on the output and computing WER.

## Speaker Recognition and Verification

- **Identification** picks which of a known set of speakers is talking: closed-set classification.
- **Verification** decides whether a clip matches one claimed speaker. It is set up as [metric learning](/docs/deep-learning/advanced-architectures#metric-learning-networks): a network (x-vectors, ECAPA-TDNN) maps each clip to an embedding, a speaker enrols by recording a reference, and a new clip is accepted if its cosine similarity to the reference passes a threshold.

### Run It Yourself: Equal Error Rate

Every threshold trades false accepts (an impostor gets in) against false rejects (the real speaker is refused). The **equal error rate** (EER) is the error at the threshold where the two rates are equal, and it is the standard single number for comparing verification systems. With simulated genuine scores centred at 0.72 and impostor scores at 0.30, the EER is about 2.7%. A bank would not run at the EER: at a threshold of 0.65, false accepts fall to almost zero but a quarter of genuine attempts are rejected.

<RunnableCode code={`import numpy as np

# Speaker verification: cosine score between an enrolment embedding and a test clip.
# Simulated scores for 1,000 genuine trials and 1,000 impostor trials.
rng = np.random.default_rng(0)
genuine  = np.clip(rng.normal(0.72, 0.10, 1000), -1, 1)
impostor = np.clip(rng.normal(0.30, 0.12, 1000), -1, 1)

thresholds = np.linspace(0, 1, 1001)
far = np.array([(impostor >= t).mean() for t in thresholds])   # false accepts
frr = np.array([(genuine < t).mean() for t in thresholds])     # false rejects
i = np.argmin(np.abs(far - frr))
print(f"equal error rate about {(far[i] + frr[i]) / 2:.3%} at threshold {thresholds[i]:.3f}")

for t in (0.45, 0.55, 0.65):
    k = int(round(t * 1000))
    print(f"threshold {t}: false accept {far[k]:.2%}, false reject {frr[k]:.2%}")

# Try it: change the impostor mean to 0.45 (a harder population, such as
# family members). The EER rises sharply, though the model did not change.`} />

## Speaker Diarization

Diarization answers "who spoke when" in a recording with several speakers, usually without knowing in advance who they are or how many. The classic pipeline runs voice activity detection (where is anyone speaking), extracts a speaker embedding for each short segment, and [clusters](/docs/machine-learning/kmeans-hierarchical-clustering) the embeddings, so each cluster is one speaker. It is a separate problem from ASR, and the two are combined to produce "Speaker A: ..., Speaker B: ..." transcripts. Overlapping speech is the hardest part, because one segment then belongs to two clusters. End-to-end neural diarization models handle overlap directly. Diarization error rate (DER) adds up missed speech, false alarms and speaker confusion as a fraction of total speech time.

## Audio Classification

Audio classification gives a clip a label: glass breaking, a dog barking, a music genre, an acoustic scene. It fits standard image methods well: treat the log-mel spectrogram as an image and apply a [CNN](/docs/deep-learning/cnns), or split it into patches for a transformer (the Audio Spectrogram Transformer). Pretraining on AudioSet, about 2 million 10-second clips labelled with 527 classes, plays the role ImageNet plays for vision.

## Speech Enhancement and Noise Suppression

Enhancement removes noise or isolates one voice. Models are trained on pairs made by adding noise to clean speech, and learn to predict either the clean spectrogram or a mask that multiplies the noisy one, the same idea as a [denoising autoencoder](/docs/deep-learning/autoencoders). For calls the model must also run in real time with only a few tens of milliseconds of look-ahead, so the latency budget shapes the architecture as much as accuracy does.

## Audio-Language Models

Audio-language models extend the [VLM design](/docs/computer-vision/modern-vision-and-multimodal#vision-language-models-and-image-text-alignment) to sound: an audio encoder feeds projected features into an LLM, the same encoder, projector and LLM layout as in [Multimodal & Generative Models](/docs/llms-genai/multimodal-generative-models). Voice assistants are moving from a cascade (ASR, then an LLM, then TTS) to such models. A cascade adds the latency of three stages and throws away tone, emphasis and pauses when it reduces speech to text; a speech-native model keeps them and can start answering sooner.

## Common Problems & Fixes

| Problem | Cause | Fix |
| --- | --- | --- |
| Whisper writes text during silence or music | The decoder's language prior, with no speech to constrain it | Voice activity detection first; suppress low-confidence segments |
| WER differs between two runs of the same model | Different text normalisation | One normaliser for every evaluation |
| ASR fails on names and jargon | Rare words absent from training text | Contextual biasing or a custom vocabulary prompt; fine-tune |
| Verification works in the lab, fails on phones | Channel mismatch between enrolment and test | Enrol on the same channel; augment with codecs and noise |
| Diarization merges two similar voices | Embeddings too close; overlap | Tune the clustering threshold; an overlap-aware model |

## When *Not* to Use It

| Situation | Better choice |
| --- | --- |
| A handful of fixed voice commands on a microcontroller | Keyword spotting with a small CNN, not full ASR |
| Live captions with under 300 ms of delay | Streaming CTC or transducer models, not a 30-second-window encoder-decoder |
| High-security authentication | Voice as one factor with others; cloned voices defeat voice alone |
| Transcribing one clear speaker offline | Plain ASR; skip diarization |

## Remember

| Idea | One line |
| --- | --- |
| CTC | One symbol per frame plus blank; merge repeats, drop blanks |
| Blank | The only way to emit a doubled letter |
| Encoder-decoder ASR | Attend over all frames, generate text; Whisper |
| WER | (S + D + I) / reference words; can exceed 1 |
| TTS | Text to mel (acoustic model), mel to waveform (vocoder) |
| Verification | Embedding plus cosine threshold; report EER |
| Diarization | VAD, segment embeddings, clustering; scored by DER |
| Speech-native assistants | Skip the cascade; keep tone and cut latency |
