# Three Sum to Zero

**Difficulty: Medium** · Pattern: Two Pointers · Concept: [General Coding (DSA) — Core Patterns to Drill](/docs/interview-prep/dsa-coding#core-patterns-to-drill)

A harder variant of [Pair With Target Sum](/practice/pair-with-target-sum): instead of finding one pair that sums to a target, find **every unique triplet** in the array that sums to `0`. The two-pointer trick still does the inner work, but now it has to run once *per candidate anchor element*, and — since the input isn't guaranteed distinct — duplicate triplets have to be actively suppressed, not just tolerated.

**Your task**: implement `three_sum_zero(nums)`, returning a list of triplets `[a, b, c]` with `a <= b <= c`, no duplicate triplets, in any order relative to each other.

<Solution>

```python
def three_sum_zero(nums):
    nums = sorted(nums)
    n = len(nums)
    result = []
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue  # skip duplicate anchors -- already covered by an earlier i
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1
    return result
```

Sorting first is what makes the two-pointer inner loop possible at all — for a fixed anchor `nums[i]`, the remaining problem is exactly [Pair With Target Sum](/practice/pair-with-target-sum) against target `-nums[i]`, run on the sorted remainder. The outer loop tries every possible anchor, so overall this is $O(n^2)$ — one $O(n)$ two-pointer sweep per anchor — a real step up from the original's plain $O(n)$.

Duplicate suppression happens at **two levels**, and both matter: `if i > 0 and nums[i] == nums[i-1]: continue` skips an anchor that's identical to the previous one (any triplet it could produce was already found when that earlier identical anchor ran); the two `while` loops after a match skip past any run of duplicate values at `left`/`right` before continuing the search, so the same triplet's values aren't matched again from an adjacent duplicate. Without both, `[-1, -1, 2]` would either get missed on the correct anchor or produced twice from the array's two `-1`s — this is the entire reason `three_sum_zero([0, 0, 0, 0])` correctly returns a single `[0, 0, 0]`, not four identical copies.
