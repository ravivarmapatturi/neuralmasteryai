**Difficulty: Easy** · Concept: [NN Layers Reference — Normalization Layers](/docs/deep-learning/nn-layers-reference#normalization-layers)

$$\text{RMSNorm}(x)_i = \frac{x_i}{\sqrt{\frac{1}{n}\sum_j x_j^2 + \epsilon}} \cdot \gamma_i$$

RMSNorm is a simplified LayerNorm: instead of subtracting the mean *and* dividing by the standard deviation, it only rescales by the root-mean-square of the activations — no mean-centering, no learned bias term. That's cheaper to compute with comparable training stability, which is exactly why it's the current default normalization in most modern LLMs (LLaMA and its successors) instead of the older LayerNorm.

<Solution>

```python
import numpy as np

def rms_norm(x, gamma, eps=1e-6):
    rms = np.sqrt(np.mean(x**2) + eps)
    return (x / rms) * gamma
```

The whole operation is one number (the RMS) computed once, then a single elementwise divide-and-scale — no second pass over the data the way LayerNorm's mean-then-variance computation needs. `rms_norm(2*x, gamma)` equalling `rms_norm(x, gamma)` above isn't a coincidence: scaling every input by a constant $c$ scales the RMS by the same $c$ (since RMS is $\sqrt{\text{mean}(x^2)}$, and $(cx)^2 = c^2x^2$), so the division exactly cancels it out — RMSNorm is invariant to the overall scale of its input, which is the real reason it works as a normalization layer at all.

`eps` matters more than it looks: without it, an all-zero input (`x = [0, 0]` above) would divide by zero. [NN Layers Reference](/docs/deep-learning/nn-layers-reference#normalization-layers) covers where RMSNorm sits relative to BatchNorm/LayerNorm/GroupNorm, and why the transformer lineage moved to normalization schemes that don't depend on batch statistics at all.
