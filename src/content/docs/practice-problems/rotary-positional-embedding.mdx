**Difficulty: Hard** · Concept: [Foundation Model Internals — Positional Encoding](/docs/llms-genai/foundation-model-internals#positional-encoding)

$$\begin{pmatrix}x'_{2i} \\ x'_{2i+1}\end{pmatrix} = \begin{pmatrix}\cos\theta_{i,p} & -\sin\theta_{i,p} \\ \sin\theta_{i,p} & \cos\theta_{i,p}\end{pmatrix}\begin{pmatrix}x_{2i} \\ x_{2i+1}\end{pmatrix}, \quad \theta_{i,p} = p \cdot \text{base}^{-2i/d}$$

RoPE encodes a token's position not by adding a position vector (the original Transformer's approach) but by *rotating* pairs of dimensions in the query/key vectors by an angle proportional to the token's position — different frequency per dimension pair, exactly like the original sinusoidal encoding's frequency schedule, but applied as a rotation instead of an addition. The payoff: the dot product between a rotated query and a rotated key ends up depending only on their *relative* position, not their absolute positions, which is exactly the property attention actually needs and is a big part of why RoPE is the dominant choice in current frontier models.

**Your task**: implement `rope(x, position, base=10000.0)` for a 1D vector `x` of even length, rotating each consecutive pair of dimensions `(x[2i], x[2i+1])` by angle `position * base^(-2i/d)`.

<Solution>

```python
import numpy as np

def rope(x, position, base=10000.0):
    d = x.shape[-1]
    i = np.arange(0, d, 2)
    freqs = base ** (-i / d)
    angles = position * freqs
    cos, sin = np.cos(angles), np.sin(angles)
    x1, x2 = x[0::2], x[1::2]
    out = np.empty_like(x)
    out[0::2] = x1 * cos - x2 * sin
    out[1::2] = x1 * sin + x2 * cos
    return out
```

`i = [0, 2, 4, ...]` indexes *pairs*, so `base ** (-i/d)` gives one frequency per pair — the same "different dimensions rotate at different rates" idea as the original sinusoidal positional encoding, just applied as a 2D rotation matrix per pair instead of added as a separate sin/cos vector. `x[0::2]`/`x[1::2]` split the vector into its even/odd halves (the two coordinates of every pair), and the four lines computing `out[0::2]`/`out[1::2]` are exactly the 2×2 rotation matrix applied elementwise across every pair at once — no explicit loop needed.

Position 0 giving back the identity (first test) makes sense directly from the formula: `angle = 0 * freq = 0` for every pair regardless of frequency, and rotating by 0 changes nothing. The norm-preservation test isn't incidental either — a rotation matrix is orthogonal by construction, so it can never change a vector's length, only its direction; this is precisely why RoPE doesn't distort the *magnitude* information a query/key vector carries, only its phase relative to other positions.
