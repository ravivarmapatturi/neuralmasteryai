# Standardize a Dataset (Z-Score Normalization)

**Difficulty: Medium** · Concept: [Probability & Statistics — Expectation, Variance, Covariance](/docs/mathematics-for-ai/probability-statistics#expectation-variance-covariance)

A direct, higher-stakes application of [Sample Mean and Variance](/practice/sample-mean-and-variance): **z-score normalization** rescales every value to "how many standard deviations from the mean is this," $z_i = \frac{x_i - \bar{x}}{\sigma}$. This is the standard feature-scaling step before training many models — gradient descent converges faster and more reliably when features share a common scale, and distance-based methods like [K-Means](/practice/kmeans-assignment-step) or [KNN](/docs/machine-learning/k-nearest-neighbors) give distorted results if one feature's raw scale dwarfs another's.

**The genuine edge case**: standardization is **undefined** when a dataset has zero variance (every value identical) — dividing by a standard deviation of `0` has no sensible answer, and a real implementation needs to fail loudly rather than produce `inf`/`nan` silently.

**Your task**: implement `standardize(data)`, returning a list of z-scores the same length as `data`. Raise `ValueError` if the data has zero variance.

<Solution>

```python
def check_raises(exc_type, func, *args):
    try:
        func(*args)
        return False
    except exc_type:
        return True


def standardize(data):
    n = len(data)
    mean = sum(data) / n
    variance = sum((x - mean) ** 2 for x in data) / n
    if variance == 0:
        raise ValueError("cannot standardize a dataset with zero variance")
    std = variance ** 0.5
    return [(x - mean) / std for x in data]
```

The mean/variance computation is exactly [Sample Mean and Variance](/practice/sample-mean-and-variance) — this problem builds directly on top of it rather than being unrelated. The `if variance == 0: raise ValueError` guard is the entire point of calling this "Medium" rather than a trivial one-line extension: without it, `[10, 10, 10]` would compute `std = 0.0` and every z-score would come out as `0/0` — Python raises `ZeroDivisionError` for plain floats there, not a silently wrong number, but that's still the *wrong* error for a caller to have to catch (it doesn't say anything about *why* — a real dataset with no variation is a meaningful, nameable failure case, not a generic arithmetic accident).

The `check_raises` helper in the starter code exists purely so this exception-raising behavior can actually be tested with a plain `assert` — no `try`/`except` is allowed inside a single-line test assertion, so wrapping the call-and-catch logic in a small reusable function is the standard workaround. This is the same reason [TreeNode](/practice/level-order-traversal)'s class definition ships as given infrastructure in tree problems rather than something the learner writes: it's scaffolding for testing the real exercise, not part of the exercise itself.
