# SwiGLU MLP Block From Scratch

**Difficulty: Medium** · Concept: [Foundation Model Internals — The MLP Block: SwiGLU](/docs/llms-genai/foundation-model-internals#the-mlp-block-swiglu)

$$\text{SwiGLU}(x) = \big(\text{SiLU}(xW_1) \odot (xW_3)\big)W_2, \quad \text{SiLU}(z) = z \cdot \sigma(z)$$

The original Transformer's feedforward block was two linear layers with a ReLU in between. Modern LLMs (LLaMA, Mistral, Gemma) instead use SwiGLU: a *gated* MLP where one linear projection (`xW1`, passed through SiLU) elementwise-gates a second, separate linear projection (`xW3`) before a final output projection (`W2`) — three weight matrices instead of two, but consistently better quality at matched parameter count, which is why it's now the default choice.

**Your task**: implement `swiglu_mlp(x, W1, W3, W2)` for a `(batch, d_model)` input and weight matrices `W1, W3: (d_model, d_ff)`, `W2: (d_ff, d_model)`.

<Solution>

```python
import numpy as np

def silu(x):
    return x / (1 + np.exp(-x))

def swiglu_mlp(x, W1, W3, W2):
    return (silu(x @ W1) * (x @ W3)) @ W2
```

`silu(x) = x * sigmoid(x)` is written here as `x / (1 + exp(-x))` — `sigmoid(x) = 1/(1+exp(-x))`, so `x * sigmoid(x) = x / (1+exp(-x))`, the same formula with one fewer intermediate array. SiLU behaves like a smooth ReLU: it's `~0` for very negative inputs and `~x` (identity) for very positive ones (confirmed by `silu(100) ≈ 100` above), but unlike ReLU it's smooth and non-monotonic near 0, which empirically trains better in practice.

The *gating* is the real structural idea, separate from which activation is used: `silu(x @ W1)` produces a per-unit "how much of this feature to let through" signal (bounded roughly `[0, ∞)` but effectively acting like a soft gate near 0), which multiplies elementwise against a completely separately-learned projection `x @ W3` — the network learns both *what* signal to compute and *how much* of it to pass along, using two independent sets of weights rather than one linear layer immediately squashed by a fixed nonlinearity. When the gate is entirely zero (the `W1_zero` test case), the whole block outputs zero regardless of `W3`/`W2` — a direct, testable confirmation that the gate really is gating, not just adding.
