**Difficulty: Easy** · Concept: [Linear Regression — The Cost Function](/docs/machine-learning/linear-regression#2-the-cost-function-mean-squared-error)

$$J = \frac{1}{n} \sum_{i=1}^{n} (\hat{y}^{(i)} - y^{(i)})^2$$

MSE is the default regression loss: average the squared difference between each prediction and its true value. It's what [Linear Regression](/docs/machine-learning/linear-regression) minimizes, and it reappears as one term inside more complex losses throughout [Deep Learning](/docs/deep-learning/loss-functions).

**Your task**: implement `mse(y_true, y_pred)` for two equal-length lists of numbers. Raise a `ValueError` if the lengths don't match, and a `ValueError` on an empty input (division by zero has no sensible answer here).

<Solution>

```python
def mse(y_true, y_pred):
    if len(y_true) != len(y_pred):
        raise ValueError("y_true and y_pred must be the same length")
    if len(y_true) == 0:
        raise ValueError("mse is undefined for empty input")
    squared_errors = [(yp - yt) ** 2 for yt, yp in zip(y_true, y_pred)]
    return sum(squared_errors) / len(squared_errors)
```

A direct transcription: build the list of per-example squared errors $(\hat{y}^{(i)} - y^{(i)})^2$, then average it. The two guard clauses matter for the same reason as [Dot Product](/practice/dot-product)'s length check — `zip` truncating silently, or `sum([]) / 0` raising a confusing `ZeroDivisionError` deep inside a training loop instead of a clear message at the call site, are both worse failure modes than an explicit, early `ValueError`.

In a real training loop this is computed on tensors (`((y_pred - y_true) ** 2).mean()` in NumPy/PyTorch) so it stays fully vectorized and differentiable — the loop version here is for understanding the mechanism, not what production code runs.
