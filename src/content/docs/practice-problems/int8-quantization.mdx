**Difficulty: Medium** · Concept: [LLM Inference Optimization — Quantization](/docs/mlops/llm-inference-optimization#quantization)

$$\text{scale} = \frac{\max(|W|)}{127}, \quad q = \text{round}\left(\frac{W}{\text{scale}}\right), \quad \hat{W} = q \cdot \text{scale}$$

Model weights are normally stored as 32- or 16-bit floats. Quantization stores them as 8-bit integers instead — a 4x (or 2x, from fp16) reduction in memory and bandwidth, which is often the real bottleneck for serving large models — at the cost of some precision loss. Symmetric per-tensor INT8 quantization is the simplest real version: find one `scale` factor that maps the weight matrix's largest-magnitude value to the INT8 range's edge (`±127`), round every other value to the nearest representable integer under that same scale, and reconstruct an approximation by multiplying back.

**Your task**: implement `quantize_int8(W)` (returning the quantized `int8` array and the scale used) and `dequantize_int8(q, scale)` (reconstructing the approximate float array).

<Solution>

```python
import numpy as np

def quantize_int8(W):
    scale = np.max(np.abs(W)) / 127.0
    if scale == 0:
        scale = 1.0
    q = np.round(W / scale)
    q = np.clip(q, -127, 127).astype(np.int8)
    return q, scale

def dequantize_int8(q, scale):
    return q.astype(np.float32) * scale
```

`scale = max(|W|) / 127` is the whole idea: dividing every weight by this one number maps the largest-magnitude weight to exactly `±127`, the edge of what `int8` can represent (`-128` to `127`, but symmetric quantization only uses `±127` so that `0` maps to exactly `0`, not some awkward asymmetric offset). Every other weight, being smaller in magnitude, lands somewhere inside that range after rounding. `np.clip` before casting to `int8` is a real safety net, not decoration — floating-point rounding could in principle push a value to `128` (just outside the valid range) even after the scale computation, and `int8` silently wraps around on overflow rather than raising an error, which would corrupt the value invisibly.

The all-zero edge case matters for the same reason [RMSNorm's `eps`](/practice/rms-normalization) does: `max(|W|) = 0` for an all-zero matrix would make `scale = 0`, and every subsequent `W / scale` a division by zero. Falling back to `scale = 1.0` in that case keeps the function well-defined (quantizing to all-zero integers, dequantizing back to all-zero floats) instead of producing `nan`.

Real production quantization ([LLM Inference Optimization](/docs/mlops/llm-inference-optimization#quantization) covers the GGUF/AWQ ecosystem built around this idea) usually quantizes per-channel or per-group rather than one scale for an entire tensor, and often quantizes activations too, not just weights — but the core scale-and-round mechanic here is the same one every one of those schemes builds on.
