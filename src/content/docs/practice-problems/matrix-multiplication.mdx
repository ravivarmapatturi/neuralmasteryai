**Difficulty: Medium** · Concept: [Linear Algebra — Matrices](/docs/mathematics-for-ai/linear-algebra#matrices)

For an $(m \times n)$ matrix $A$ and an $(n \times p)$ matrix $B$, the product $C = AB$ is $(m \times p)$, where each entry $C_{ij} = \sum_k A_{ik} B_{kj}$ — the dot product of $A$'s row $i$ with $B$'s column $j$. This is the single operation every linear layer in a neural network runs on every forward pass.

**Your task**: implement `matmul(A, B)` for matrices represented as lists of lists of numbers (no NumPy). Raise a `ValueError` if the inner dimensions don't match (`A`'s number of columns must equal `B`'s number of rows).

<Solution>

```python
def matmul(A, B):
    rows_a, cols_a = len(A), len(A[0])
    rows_b, cols_b = len(B), len(B[0])
    if cols_a != rows_b:
        raise ValueError(f"shape mismatch: {rows_a}x{cols_a} @ {rows_b}x{cols_b}")

    result = [[0] * cols_b for _ in range(rows_a)]
    for i in range(rows_a):
        for j in range(cols_b):
            result[i][j] = sum(A[i][k] * B[k][j] for k in range(cols_a))
    return result
```

Three nested loops, directly matching $C_{ij} = \sum_k A_{ik} B_{kj}$: the outer two (`i`, `j`) walk every cell of the output, and the innermost `sum(...)` computes that cell as a dot product — literally [Dot Product From Scratch](/practice/dot-product) run once per output cell. The shape check happens before any work starts, since a silent shape mismatch (e.g. feeding a $(3\times4)$ activation into a $(3\times2)$ weight matrix) is exactly the class of bug that should fail loudly, not produce a wrong-shaped result.

This is $O(m \cdot n \cdot p)$ — fine for small matrices, but real deep learning frameworks use BLAS-backed vectorized multiplication (`A @ B` in NumPy, or a GPU matmul kernel in PyTorch), which is orders of magnitude faster via cache-friendly memory access and hardware parallelism, not a different algorithm in principle.
