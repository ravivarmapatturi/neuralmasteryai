**Difficulty: Medium** · Concept: [Foundation Model Internals — Sampling: From Logits to a Token](/docs/llms-genai/foundation-model-internals#sampling-from-logits-to-a-token)

Top-k sampling keeps a fixed number of candidate tokens at every step, which is awkward: a genuinely confident prediction (one token overwhelmingly likely) still keeps `k` candidates even if the rest have almost no probability, while a genuinely ambiguous prediction (probability spread thin across many tokens) is forced down to the same fixed `k`. Top-p (nucleus) sampling fixes this by keeping the *smallest* set of tokens whose cumulative probability exceeds a threshold `p` — the set size adapts automatically to how peaked or flat the distribution actually is, which is why top-p is generally preferred over a fixed top-k in production systems.

**Your task**: implement `top_p_filter(probs, p)` for a 1D array of token probabilities (already summing to 1), returning a same-shape array with every token outside the top-p nucleus zeroed out and the remaining probabilities renormalized to sum to 1.
