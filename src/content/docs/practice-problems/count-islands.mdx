Given a 2D grid of `1`s (land) and `0`s (water), count the number of **islands** — groups of `1`s connected horizontally or vertically (not diagonally). This is a grid dressed up as a graph problem: each land cell is a node, each cell is implicitly connected to its up/down/left/right neighbors, and an "island" is exactly a **connected component**.

**Your task**: implement `count_islands(grid)`, using DFS (or BFS — either correctly solves this) to explore each island fully before moving to the next, without recounting cells or mutating the input grid.

```python
def count_islands(grid):
    if not grid:
        return 0
    rows, cols = len(grid), len(grid[0])
    visited = set()

    def explore_island(start_r, start_c):
        stack = [(start_r, start_c)]
        while stack:
            r, c = stack.pop()
            if (r, c) in visited:
                continue
            if r < 0 or r >= rows or c < 0 or c >= cols:
                continue
            if grid[r][c] == 0:
                continue
            visited.add((r, c))
            stack.extend([(r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)])

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 1 and (r, c) not in visited:
                count += 1
                explore_island(r, c)
    return count
```

The outer double loop scans every cell exactly once looking for an **unvisited** `1` — that's the start of a new island, since a `1` already in `visited` was already claimed by an island explored earlier. `explore_island` is DFS with an explicit stack rather than recursive calls (safer against Python's recursion limit on a large grid, and the same iterative-stack style [Largest Rectangle in a Skyline](/practice/largest-rectangle-in-skyline) used) — it floods outward from one land cell, marking every reachable land cell as visited, so by the time it returns, the *entire* island has been consumed and the outer loop's later cells belonging to that same island get correctly skipped.

Using a separate `visited` set instead of mutating `grid` in place (a common shortcut: set visited cells to `0` directly) matters for the same reason [Numerical Gradient](/practice/numerical-gradient) copies its input rather than mutating it — the caller's grid stays intact after the call, which matters the moment anything else needs to read the original grid afterward.

The four-corners test case (`[[1,0,1],[0,0,0],[1,0,1]]` → 4) is the one that actually exercises the "diagonal doesn't count as connected" rule — each corner `1` has no horizontal/vertical `1` neighbor, so all four are separate islands despite sitting diagonally adjacent to each other.
