# MLOps Overview

<ELI5>

A model that works once is like a recipe that works in one kitchen. MLOps records the ingredients, checks each batch, prepares the serving kitchen, and watches the result after customers arrive. If the data or the world changes, the team can trace what happened and decide whether to update or roll back.

</ELI5>

## Why it exists

Machine-learning systems keep changing after a notebook run: code, data, dependencies, and production traffic all evolve. MLOps makes those changes traceable and creates a feedback loop for safe updates.


## The big picture

The learning path follows a model from checked data to measured production feedback. Notice that the final operational stage informs the next training run.

## Common mistakes

| Mistake | Why it happens | Fix |
| :--- | :--- | :--- |
| Treat deployment as the end of the lifecycle | Production inputs and service health change | Feed monitoring evidence into retraining or rollback |
| Lose data and run lineage | Teams cannot reproduce the model | Version datasets, settings, and artifacts |
| Monitor only service uptime | The service can be healthy while model quality drifts | Track both system and model signals |
