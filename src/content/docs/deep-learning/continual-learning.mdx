# Continual Learning

Every page before this one assumes a network trains on one dataset, once, and is then frozen. Real systems don't stay still. A fraud model must learn this month's scams, a robot new objects, a language model new facts, a new product's documentation and a new safety policy. **Continual learning** (also called lifelong or incremental learning) asks what happens when a trained network has to learn something new, and the data it originally learned from is no longer available, or too large to retrain on. The short answer is that it forgets, quickly and badly. This page explains why, measures it, and goes through the three families of mitigation: penalizing changes to important weights (elastic weight consolidation), replaying old examples, and giving new tasks their own parameters. It ends with what this means for language models, which are fine-tuned again and again.

<ELI5>

Imagine a whiteboard covered in notes for one subject. Now someone asks you to write notes for a second subject, and there's no spare space. If you write wherever you like, you'll scribble over the first subject's notes, and soon you can't read them.

You could write only in the corners the first subject barely used (that's EWC). You could keep a few index cards from the first subject and rewrite them as you go (that's replay). Or you could buy a second, smaller whiteboard for the new subject (that's parameter isolation).

A neural network's weights are the whiteboard, and training on a new task writes wherever the new task's gradient says, regardless of what was there. Everything below is those three strategies made exact.

</ELI5>

## 1. Catastrophic Forgetting

Train a network on task A until it's good. Then train the same network on task B, using only task B's data. Accuracy on task A typically falls sharply, often towards chance, within a few epochs. McCloskey and Cohen named this **catastrophic interference** in 1989, and it's still the central problem of the field.

The cause is in the update rule. Gradient descent on task B minimizes task B's loss and nothing else:

$$
\theta \leftarrow \theta - \alpha\, \nabla_\theta L_B(\theta)
$$

Nothing in $L_B$ refers to task A. Every weight moves as far as task B's gradient says, whether or not task A depended on it. Because a network's knowledge is spread across shared weights rather than stored in separate places, task B's changes cut straight through task A's.

### The three settings

How hard the problem is depends on what changes between tasks:

- **Task-incremental**: the model is told which task it's doing at test time, and can use a separate output head per task. The easiest setting.
- **Domain-incremental**: the same output classes, but the input distribution changes, such as the same digits with a new camera, or the same medical diagnosis at a new hospital. The experiment below is of this kind.
- **Class-incremental**: new classes appear over time and the model must choose among all classes seen so far, without being told which task an input comes from. The hardest setting: a naive model trained on classes 5 to 9 typically stops predicting 0 to 4 at all.

## 2. Stability and Plasticity

Any fix has to balance two opposing needs. **Stability** is keeping what was learned. **Plasticity** is learning new things. A network whose weights can't move is perfectly stable and learns nothing; one whose weights move freely learns everything new and forgets everything old. Every continual-learning method sets a point on that trade-off, and it's measured by two numbers:

- **Forgetting**: how much accuracy on old tasks drops after learning new ones.
- **Forward transfer**: how well, or how fast, new tasks are learned, compared with training on them alone.

The upper bound to compare against is **joint training**, retraining on all tasks' data together, which is usually what continual learning is trying to avoid having to do.

## 3. Regularization: Elastic Weight Consolidation

The first family keeps training on task B only, but adds a penalty for moving weights that mattered to task A. The question is which weights mattered.

**Elastic weight consolidation** (EWC; Kirkpatrick et al., 2017) answers it with the **Fisher information**. For each weight $\theta_i$, the diagonal Fisher

$$
F_i = \mathbb{E}\left[\left(\frac{\partial \log p(y \mid \mathbf{x}; \theta)}{\partial \theta_i}\right)^2\right]
$$

measures how sharply task A's log-likelihood changes when $\theta_i$ moves, so large $F_i$ means the weight is important to task A. The training loss for task B becomes

$$
L(\theta) = L_B(\theta) + \frac{\lambda}{2} \sum_i F_i \left(\theta_i - \theta^*_{A,i}\right)^2
$$

where $\theta^*_A$ are the weights at the end of task A. Important weights are held near their old values as if by a stiff spring; unimportant ones are free to change. The name is the image of each weight on an elastic, of varying stiffness, tied to where it was.

The derivation is Bayesian: after task A, the posterior over weights is approximated by a Gaussian centred at $\theta^*_A$ with precision given by the Fisher, and the penalty is its negative log, carried forward as a prior for task B.

**Its limits.** The diagonal approximation ignores how weights interact, the Gaussian approximation holds only near $\theta^*_A$, and a separate penalty term per previous task accumulates. When one weight serves many tasks at once, a single importance score can't say which of its uses must be protected. **Synaptic intelligence** and **memory-aware synapses** are relatives that estimate importance differently. **Learning without forgetting** (Li and Hoiem, 2016) is a different regularizer: it keeps the new model's *outputs* on new data close to the old model's, by distillation, instead of constraining the weights.

## 4. Replay

The second family is blunt: keep some of task A's data and train on it alongside task B's. If the network still sees old examples, their loss pushes back against forgetting directly.

- **Experience replay** stores a small buffer, often a few percent of each old task, and mixes it into every new batch. Choosing *which* examples to keep matters, and simple random selection ("reservoir sampling" for streams) is a strong baseline.
- **Generative replay** (Shin et al., 2017) trains a generative model on old tasks and samples synthetic old examples instead of storing real ones, useful where data can't be kept for privacy or legal reasons, at the cost of training and trusting the generator.
- **Constrained updates** such as GEM and A-GEM use the stored examples differently: they project task B's gradient so that it doesn't increase the loss on the buffer.

Replay is simple and, in practice, usually the most effective family. Its costs are memory, which grows with the number of tasks, and the need to be allowed to keep old data at all.

## 5. Parameter Isolation

The third family avoids interference by construction: give each task its own parameters.

- **Progressive networks** (Rusu et al., 2016) add a new column of layers for each task, freeze the old columns, and connect new to old so knowledge can still transfer forwards.
- **Masking** methods such as PackNet and HAT reserve a subset of the existing weights for each task and freeze it.
- **Adapters** keep a shared base frozen and train a small module per task, such as a [LoRA](/docs/llms-genai/training-pipeline#parameter-efficient-fine-tuning-peft) adapter. Switching tasks means switching adapters.

There's no forgetting, because old tasks' parameters are never touched. The costs are that parameters grow with the number of tasks, and that the model usually needs to know which task an input belongs to, which is exactly what class-incremental learning doesn't provide.

## 6. Measuring Forgetting

Here is the problem and the first two families measured on scikit-learn's handwritten digits. Task A is the digits as they are. Task B is the *same* digits with their 64 pixels shuffled by one fixed permutation, a new input domain with the same ten classes. A small network is trained on A, then on B, four ways: naively; with EWC, using the empirical Fisher computed from per-example gradients; with replay of 70 task-A examples (5% of its training set); and jointly on both, as the upper bound.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import load_digits

torch.manual_seed(0)
d = load_digits()
X, y = torch.tensor(d.data / 16.0, dtype=torch.float32), torch.tensor(d.target)
perm = torch.randperm(64)                                  # task B: the same digits, pixels shuffled
tasks = {"A": (X[:1400], y[:1400], X[1400:], y[1400:]),
         "B": (X[:1400, perm], y[:1400], X[1400:, perm], y[1400:])}

def make_net():
    torch.manual_seed(1)
    return nn.Sequential(nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 10))

def fit(net, Xs, ys, steps=600, penalty=None):
    opt = torch.optim.Adam(net.parameters(), lr=1e-3)
    for _ in range(steps):
        loss = F.cross_entropy(net(Xs), ys) + (penalty(net) if penalty else 0)
        opt.zero_grad(); loss.backward(); opt.step()

def acc(net, task):
    _, _, Xt, yt = tasks[task]
    with torch.no_grad():
        return (net(Xt).argmax(1) == yt).float().mean().item()

def ewc_penalty(net, strength=2000):
    """Elastic weight consolidation: a quadratic pull back to the task-A weights, weighted by the
    diagonal Fisher information (mean squared gradient of the log-likelihood on task-A data)."""
    Xa, ya = tasks["A"][:2]
    params = {k: v.detach() for k, v in net.named_parameters()}
    def example_loss(p, x, t):
        return F.cross_entropy(torch.func.functional_call(net, p, (x[None],)), t[None])
    per_example = torch.func.vmap(torch.func.grad(example_loss), in_dims=(None, 0, 0))(params, Xa, ya)
    fisher = [(g ** 2).mean(0) for g in per_example.values()]   # mean squared per-example gradient
    anchor = [p.detach().clone() for p in net.parameters()]
    return lambda n: strength / 2 * sum((f * (p - a) ** 2).sum() for f, p, a in zip(fisher, n.parameters(), anchor))

results = {}
for method in ("naive", "EWC", "replay 5%", "joint"):
    net = make_net()
    XA, yA = tasks["A"][:2]
    XB, yB = tasks["B"][:2]
    if method == "joint":                                  # upper bound: both tasks' data at once
        fit(net, torch.cat([XA, XB]), torch.cat([yA, yB]), steps=1200)
        results[method] = (None, acc(net, "A"), acc(net, "B")); continue
    fit(net, XA, yA)
    before = acc(net, "A")
    if method == "naive":
        fit(net, XB, yB)
    elif method == "EWC":
        fit(net, XB, yB, penalty=ewc_penalty(net))
    else:                                                  # keep 70 task-A examples and mix them in
        keep = torch.randperm(len(XA))[:70]
        fit(net, torch.cat([XB, XA[keep]]), torch.cat([yB, yA[keep]]))
    results[method] = (before, acc(net, "A"), acc(net, "B"))

for method, (before, a, b) in results.items():
    first = f"after A: task A {before:.2f}" if before is not None else "both tasks at once"
    second = "after B" if before is not None else "trained"
    print(f"{method:10s} {first:18s} | {second}: task A {a:.2f}, task B {b:.2f}")
```

```text
naive      after A: task A 0.92 | after B: task A 0.39, task B 0.91
EWC        after A: task A 0.92 | after B: task A 0.76, task B 0.86
replay 5%  after A: task A 0.92 | after B: task A 0.82, task B 0.91
joint      both tasks at once | trained: task A 0.91, task B 0.93
```

Reading the rows:

- **Naive training forgets catastrophically.** Task A accuracy falls from 0.92 to 0.39 while the network learns task B, and nothing about task A changed. Its weights were simply repurposed.
- **EWC trades plasticity for stability.** It keeps task A at 0.76 by resisting changes to important weights, and pays for it with lower accuracy on task B (0.86 against 0.91): the stability-plasticity trade-off in two numbers. A larger penalty strength would push further in both directions.
- **Replay of 5% of the old data does better on both**: task A 0.82, task B 0.91. Seventy stored examples carry much of task A's knowledge forward.
- **Joint training is the ceiling**, 0.91 and 0.93, and the gap between it and the best continual method is the price of not having all the data at once.

These numbers are from one small run. On harder benchmarks the ordering is usually the same, with replay strongest per unit of effort, though how much each method helps depends heavily on the setting.

## 7. Continual Learning for Language Models

The problem matters most today for large language models, which are continually updated: continued pretraining on new data or a new language, rounds of instruction tuning, domain fine-tunes, safety updates. Each is training on new data without the original pretraining corpus in the mix, and each risks degrading earlier abilities.

What has held up at this scale:

- **Replay, in the form of data mixing.** Continued pretraining mixes a fraction of general pretraining-style data back in with the new domain's data, and fine-tuning mixes in general instruction data. Even a few percent markedly reduces forgetting.
- **Learning-rate care.** Continued pretraining re-warms the learning rate to a lower peak than the original run and decays it again; too high a peak makes the model forget more of what it knew.
- **Adapters.** LoRA and similar methods update far fewer parameters. Biderman et al. (2024) found that LoRA "learns less and forgets less" than full fine-tuning: it changes the model less in both directions.
- **The training method matters.** Recent work (Shenfeld et al., 2025) found that fine-tuning with on-policy reinforcement learning tends to forget less than supervised fine-tuning to the same new-task performance, because it moves the model's output distribution less.
- **Not training at all.** For new *facts*, retrieval ([RAG](/docs/llms-genai/rag)) puts information in the prompt instead of the weights, avoiding forgetting entirely, which is one reason it's usually preferred over fine-tuning for knowledge.

Weight-importance methods like EWC have transferred less well to large language models. A single importance score per weight is a coarse tool when each weight takes part in many unrelated computations, a phenomenon related to [superposition](/docs/interpretability/deep-learning-and-llm-interpretability#sparse-autoencoders-and-superposition).

<GoDeeper title="Go deeper: why bigger and pretrained models forget less">

Two observations from the literature fit together.

Larger networks forget less under the same sequence of tasks. With more capacity, the solutions for task A and task B are more likely to coexist in different directions of weight space, and the gradient for task B is more likely to be nearly orthogonal to the directions task A depends on.

Pretrained networks forget less than ones trained from scratch, and adapt with smaller weight changes. Starting from a broad pretrained representation, a new task often needs only a small adjustment, and a small move in weight space disturbs less of what was there. That's also why adapters and low learning rates help: they keep the update small.

Neither removes forgetting. A large pretrained model fine-tuned hard on a narrow task can still lose general abilities, which is why evaluation on a broad suite of earlier tasks belongs in every fine-tuning run.

</GoDeeper>

## 8. Choosing an Approach

| Question | If yes | If no |
|---|---|---|
| Can you keep some old data? | Replay, mixed into every batch | EWC, distillation from the old model, or generative replay |
| Is the number of tasks small and known? | Parameter isolation, such as one adapter per task | Replay or regularization, which keep the model size fixed |
| Does the model know which task an input belongs to? | Task-specific heads or adapters are simple | You're in the class-incremental setting; replay matters most |
| Is the new information mostly facts? | Retrieval rather than training | Fine-tune with data mixing and a broad evaluation suite |
| Can you afford to retrain on everything? | Joint retraining, the ceiling for every method | Continual learning, with forgetting measured explicitly |

## 9. When *Not* to Use Continual Learning Methods

| Situation | Better choice |
|---|---|
| All past data is available and retraining is affordable | Retrain jointly on everything; it's simpler and better |
| The new information is facts that change often | Retrieval into a frozen model |
| A one-off fine-tune where earlier abilities don't matter | Plain fine-tuning |
| EWC on a very large model with many prior updates | Data mixing and adapters, which scale better |
| Parameter isolation with an open-ended stream of tasks | Replay or regularization, whose cost doesn't grow per task |

## Remember

| Idea | In one line |
|---|---|
| Catastrophic forgetting | Training on B moves shared weights with no regard for A |
| Settings | Task-, domain- and class-incremental; class-incremental is hardest |
| Trade-off | Stability (keep old) versus plasticity (learn new); joint training is the ceiling |
| EWC | Quadratic pull to old weights, weighted by Fisher importance |
| Replay | Mix a small buffer of old examples into training; simple and strong |
| Isolation | Separate parameters per task; no interference, but growth and task identity needed |
| Measured | Naive 0.92 to 0.39 on task A; EWC 0.76; replay of 5% 0.82; joint 0.91 |
| LLMs | Data mixing, careful learning rates, adapters, and retrieval for facts |
