# Initialization, Regularization and Learning-Rate Schedules

With [activations](/docs/deep-learning/activation-functions), a [loss](/docs/deep-learning/loss-functions) and an [optimizer](/docs/deep-learning/optimizers) chosen, three decisions remain before a training run can start, and each can quietly decide whether it succeeds. **Initialization**: what values do the weights start at? Get the scale wrong and the signal vanishes or explodes before the first update. **Regularization**: how do you stop a network with more parameters than examples from memorizing them? **Scheduling**: should the learning rate stay fixed, or change as training goes on? This page derives the standard initializations from a variance argument and measures what happens without them across fifty layers, goes through the regularization toolkit and what each method actually assumes, and explains the schedules used to train today's large models.

<ELI5>

Think of tuning a long chain of guitar effects pedals before a concert. If every pedal starts with its volume knob too low, the sound fades to nothing by the end of the chain; too high, and it's deafening distortion. You want every knob set so the sound comes out about as loud as it went in. That's initialization.

During rehearsal, the band could memorize one exact performance of each song, every slip included, and then fall apart when the venue sounds different. Making them practise in different rooms, with someone occasionally missing, forces them to really know the songs. That's regularization.

And when tuning, you turn the knobs in big moves at first, then smaller and smaller ones as you get close. That's a learning-rate schedule. Everything below is those three habits made exact.

</ELI5>

## 1. Why Initialization Matters

Two things go wrong with a bad starting point.

**Symmetry.** If every weight in a layer starts at the same value (zero, say), every neuron in that layer computes the same output and receives the same gradient, so after any number of updates they're still identical. A layer of 512 neurons acts like one. Random initialization breaks the symmetry, so neurons can learn different features.

**Scale.** A neuron's pre-activation is a sum over its $n$ inputs, $z = \sum_{i=1}^{n} w_i x_i$. If the weights and inputs are independent with zero mean, the variances add:

$$
\operatorname{Var}(z) = n\, \operatorname{Var}(w)\, \operatorname{Var}(x)
$$

So each layer multiplies the variance of the signal by $n \operatorname{Var}(w)$, times whatever the activation does to it. Over $L$ layers that factor is raised to the $L$-th power. Slightly less than 1 per layer and the signal vanishes; slightly more and it explodes, in the forward pass and, by the same argument, in the gradients of the backward pass ([Training Deep Networks](/docs/deep-learning/training-deep-networks#vanishing-exploding-gradients)). Initialization chooses $\operatorname{Var}(w)$ to make the per-layer factor 1.

## 2. Xavier and He, Derived

**For tanh and sigmoid-like activations**, which are close to the identity near zero, keeping $n \operatorname{Var}(w) = 1$ keeps the variance steady:

$$
\operatorname{Var}(w) = \frac{1}{n_\text{in}}
$$

Glorot and Bengio (2010) noted the backward pass wants $\operatorname{Var}(w) = 1/n_\text{out}$ by the same argument, and compromised on

$$
\operatorname{Var}(w) = \frac{2}{n_\text{in} + n_\text{out}}
$$

This is **Xavier** (or Glorot) initialization. The plain $1/n_\text{in}$ version is also called **LeCun** initialization, and it's the one SELU's self-normalizing property requires.

**For ReLU**, the activation zeroes every negative input, which is half of them, so it halves the second moment of the signal at every layer. He et al. (2015) compensated by doubling the weight variance:

$$
\operatorname{Var}(w) = \frac{2}{n_\text{in}}
$$

This is **He** (or Kaiming) initialization, and it's the default for ReLU-family networks. Biases are usually started at zero. Both schemes come in normal and uniform versions with the same variance: a uniform distribution on $[-a, a]$ has variance $a^2/3$.

### Measured through fifty layers

The variance argument predicts exactly what the following script measures: push a batch of random inputs through fifty 512-wide layers, with no training, and print the spread of the final activations under each scheme.

```python
import math
import torch

torch.manual_seed(0)
DEPTH, WIDTH = 50, 512
x0 = torch.randn(1000, WIDTH)

def activation_std(act, std_fn):
    x = x0
    for _ in range(DEPTH):
        W = torch.randn(WIDTH, WIDTH) * std_fn(WIDTH)
        x = act(x @ W)
    return x.std().item()

schemes = {"N(0, 0.01^2)": lambda n: 0.01, "Xavier 1/sqrt(n)": lambda n: 1 / math.sqrt(n), "He sqrt(2/n)": lambda n: math.sqrt(2 / n)}
for act_name, act in [("tanh", torch.tanh), ("ReLU", torch.relu)]:
    for name, std_fn in schemes.items():
        print(f"{act_name:4s} + {name:17s} activation std after {DEPTH} layers: {activation_std(act, std_fn):.2e}")

# Warmup then cosine decay: the learning rate at a few steps of a 10,000-step run.
def lr_at(step, peak=3e-4, warmup=500, total=10_000, floor=3e-5):
    if step < warmup:
        return peak * (step + 1) / warmup
    progress = (step - warmup) / (total - warmup)
    return floor + 0.5 * (peak - floor) * (1 + math.cos(math.pi * progress))

for s in (0, 250, 500, 2500, 5000, 7500, 9999):
    print(f"step {s:5d}: learning rate {lr_at(s):.1e}")
```

```text
tanh + N(0, 0.01^2)      activation std after 50 layers: 5.10e-33
tanh + Xavier 1/sqrt(n)  activation std after 50 layers: 9.66e-02
tanh + He sqrt(2/n)      activation std after 50 layers: 5.54e-01
ReLU + N(0, 0.01^2)      activation std after 50 layers: 9.65e-41
ReLU + Xavier 1/sqrt(n)  activation std after 50 layers: 2.32e-08
ReLU + He sqrt(2/n)      activation std after 50 layers: 9.32e-01
step     0: learning rate 6.0e-07
step   250: learning rate 1.5e-04
step   500: learning rate 3.0e-04
step  2500: learning rate 2.7e-04
step  5000: learning rate 1.8e-04
step  7500: learning rate 7.4e-05
step  9999: learning rate 3.0e-05
```

The first six lines confirm the derivation:

- **Small fixed initialization kills the signal** with either activation: an activation spread of $10^{-33}$ or $10^{-41}$ means the output no longer depends on the input. With a standard deviation of 0.01 and 512 inputs, each layer multiplies the spread by about $0.01 \times \sqrt{512} = 0.23$.
- **Xavier suits tanh and fails ReLU.** With tanh it keeps the signal alive at 0.1 after fifty layers (tanh shrinks large values slightly, so a slow decline is expected). With ReLU it loses half the variance at each layer, $2^{-25} \approx 3 \times 10^{-8}$ in spread, as measured.
- **He suits ReLU**, keeping the spread near 1 after fifty layers. (With tanh it's slightly too large but still workable.)

**Other schemes.** **Orthogonal** initialization uses a random orthogonal matrix, which preserves the norm of every vector exactly; it helped plain RNNs, which apply one matrix many times. Residual networks often initialize the last layer of each residual branch at zero or scaled down by $1/\sqrt{\text{depth}}$, so each block starts as nearly the identity and the residual stream doesn't grow with depth (GPT-2 scaled by $1/\sqrt{2 \times \text{layers}}$). And with normalization layers in every block, as in modern transformers, the network is much less sensitive to initialization, though the scale still affects early training stability.

## 3. Regularization: Controlling Overfitting

A network with millions of parameters can fit its training set perfectly, noise included. **Regularization** is anything that pushes it towards solutions that generalize instead. The methods differ in what they assume about a good solution.

### Penalties on the weights

**L2 regularization** adds $\tfrac{\lambda}{2}\sum w^2$ to the loss, assuming small weights generalize better, the same idea as [ridge regression](/docs/machine-learning/ridge-regression). Its gradient is $\lambda w$, so with plain gradient descent every step shrinks each weight by a factor $(1 - \alpha\lambda)$: **weight decay**. With adaptive optimizers the two are *not* the same, and decay should be applied directly to the weights, which is what [AdamW](/docs/deep-learning/optimizers#adam-and-its-descendants) does. In practice, weight decay of about 0.01 to 0.1 with AdamW is applied to weight matrices and usually not to biases and normalization parameters.

**L1 regularization** adds $\lambda\sum\lvert w\rvert$, pushing weights to exactly zero like [lasso](/docs/machine-learning/lasso-regression). It's rarely used on whole deep networks, since sparse weights don't make dense hardware faster, but appears where sparsity itself is the goal.

### Noise during training

**Dropout** (Srivastava et al., 2014) zeroes each activation with probability $p$ during training and scales the survivors by $1/(1-p)$, so expected values are unchanged and nothing needs adjusting at inference, when dropout is off. No unit can count on any particular other unit, so the network learns redundant features; it behaves like an average over an ensemble of sub-networks sharing weights. Typical rates are 0.1 in transformers and up to 0.5 in older fully connected layers. **DropConnect** drops individual weights instead of activations, and **stochastic depth** drops whole residual blocks, which regularizes very deep networks and speeds up their training.

**Data augmentation** creates new training examples by transformations that shouldn't change the label: crops, flips, colour changes and mixing images (mixup, CutMix) in vision; noise and time-stretching in audio; back-translation in text. It assumes the model should be invariant to those changes, and builds that in without touching the architecture. In vision it's often the most effective regularizer.

### Softer targets and earlier stops

**Label smoothing** trains towards, say, 0.9 on the true class and the remaining 0.1 spread over the others, instead of exactly 1 and 0. It stops the model driving its logits towards infinity to fit hard targets, and generally improves calibration ([Loss Functions](/docs/deep-learning/loss-functions) covers it with cross-entropy).

**Early stopping** watches the validation loss and keeps the checkpoint where it was lowest, rather than training for a fixed number of epochs. It's free, and it's a regularizer: limiting the number of steps limits how far the weights can travel from their small initial values.

### Data, the strongest regularizer

The surest cure for overfitting is more data. Large language models are often pretrained with little or no dropout because they see each token about once, so there is nothing to memorize. Regularization matters most when data is scarce relative to model size, such as fine-tuning on a few thousand examples.

## 4. What the Learning Rate Should Do Over Time

A fixed learning rate is a compromise. Early on, the weights are far from good values and large steps make fast progress. Later, large steps bounce around the bottom of the loss valley, because each mini-batch gradient is noisy, and only small steps settle into it. And at the very start there's a separate danger: the weights are random, gradients can be large and erratic, and Adam's moment estimates are empty, so a full-size first step can throw training into a bad region it never recovers from.

A **schedule** changes the learning rate during training to match. Three phases are standard:

1. **Warmup**: increase linearly from near zero to the peak over the first few hundred or thousand steps.
2. **The bulk of training** at or near the peak.
3. **Decay** towards a small final value, where the loss usually drops noticeably as the optimizer stops bouncing and settles.

## 5. Common Schedules

<LrSchedulesDiagram />

- **Step decay**: multiply the learning rate by a factor such as 0.1 at fixed epochs. The classic ResNet recipe. Loss curves show a visible drop at each step.
- **Exponential decay**: $\alpha_t = \alpha_0 e^{-kt}$. Smooth, but its shape is fixed in advance regardless of progress.
- **Cosine decay** (Loshchilov and Hutter, 2016): follow half a cosine from the peak to a minimum, slow at first, fastest in the middle, gentle at the end:

$$
\alpha_t = \alpha_\text{min} + \tfrac{1}{2}\left(\alpha_\text{max} - \alpha_\text{min}\right)\left(1 + \cos\frac{\pi t}{T}\right)
$$

Warmup followed by cosine decay to about 10% of the peak has been the standard schedule for training transformers. The script in section 2 computed it for a 10,000-step run with 500 warmup steps and a peak of $3 \times 10^{-4}$: the rate climbs from almost nothing to the peak at step 500, and is still at 90% of it at step 2,500, 60% at the halfway point and 10% at the end.

- **Cosine with warm restarts**: repeat the cosine, jumping back to the peak each time. The jumps can move the model out of a poor region, at the cost of temporary loss spikes.
- **One-cycle** (Smith, 2018): ramp up to an unusually high peak and back down over a single cycle. The high-learning-rate phase acts as a regularizer, and it often trains small and medium models fast.
- **Reduce on plateau**: cut the rate by a factor whenever validation loss stops improving for a set number of epochs. It adapts to the actual curve, which suits fine-tuning where validation is cheap.
- **Polynomial and linear decay**: $\alpha_t = \alpha_0 (1 - t/T)^p$; with $p = 1$, the linear decay often used for BERT-style fine-tuning.

### Warmup-stable-decay

A recent change in large-model training is the **warmup-stable-decay (WSD)** schedule, also called trapezoidal: warm up, hold the peak learning rate constant for most of training, then decay quickly over the final 10 to 20% of steps. Cosine's drawback is that it needs the total number of steps fixed in advance: stop early and the learning rate was never decayed, so you can't take a good checkpoint from the middle. With WSD, any point in the stable phase can be branched into a short decay to produce a finished model, which makes it possible to continue training, or to compare data mixtures at several training lengths, without rerunning from scratch. MiniCPM (2024) popularized it, and studies since have found it matches cosine at the same final step count.

<GoDeeper title="Go deeper: why the loss drops sharply when the learning rate decays">

Training curves often show a long, slowly declining plateau followed by a sharp fall when the learning rate is cut. A useful picture explains it.

With a noisy mini-batch gradient, gradient descent doesn't settle at the bottom of the loss valley; it bounces around it, and the size of the bounce is proportional to the learning rate times the gradient noise. During the high-learning-rate phase, the optimizer is moving the weights a long way, finding a good *region*, while bouncing high up its walls. Decaying the learning rate shrinks the bounce, so the weights settle towards the floor of the region already found, and the loss drops.

That's why both phases matter. Too short a high phase, and the region found is worse. No decay phase, and the model never settles into it. It's also why WSD works: the stable phase does the exploring, and a short final decay does the settling, so the settling can be attached to any point in the run.

</GoDeeper>

## 6. When *Not* to Use Each

| Situation | Better choice |
|---|---|
| Xavier initialization in a deep ReLU network | He initialization, which accounts for ReLU zeroing half its inputs |
| L2 regularization mixed into the loss with Adam | AdamW's decoupled weight decay |
| Weight decay on biases and normalization gains | Exclude them; decay is meant for weight matrices |
| Heavy dropout in a large model trained once over huge data | Little or none; there's nothing to memorize and it slows learning |
| Augmentations that change the label, such as flipping digits like 6 and 9 | Only label-preserving transformations |
| A cosine schedule when you don't know how long you'll train | Warmup-stable-decay, which can be decayed at any point |
| No warmup with Adam on a transformer | A few hundred to a few thousand warmup steps |

## Remember

| Idea | In one line |
|---|---|
| Symmetry | Identical starting weights stay identical; initialize randomly |
| Scale | Each layer multiplies variance by $n \operatorname{Var}(w)$; aim for 1 |
| Xavier / LeCun | $\operatorname{Var}(w) = 1/n_\text{in}$ (or $2/(n_\text{in}+n_\text{out})$) for tanh-like activations |
| He | $\operatorname{Var}(w) = 2/n_\text{in}$ for ReLU, which halves the signal's second moment |
| Weight decay | Shrink weights each step; with Adam, use AdamW |
| Dropout | Zero activations at random in training, scale the rest; off at inference |
| Augmentation, label smoothing, early stopping | Invariance by construction; softer targets; stop at the best validation point |
| Data | The strongest regularizer; large pretraining runs use little else |
| Schedules | Warm up, train near the peak, decay; cosine is standard, WSD is decay-on-demand |
