# Frameworks — Roadmap

## Why it exists

Frameworks sit at different points in the ML lifecycle. The path starts with core model tools, moves to LLM/agent orchestration, then covers serving and operations.

- [x] LangChain — chains, retrievers, agents
- [x] LlamaIndex — data indexing and retrieval for RAG
- [x] An MCP SDK (Python or TypeScript) — building MCP servers/clients
- [x] An agent framework (e.g. LangGraph, CrewAI) for multi-agent orchestration

- [x] Model serving: vLLM, TorchServe, Triton
- [x] Containerization & deployment basics (Docker)
- [x] CI/CD for ML: automated retraining and evaluation pipelines
- [x] Observability for LLM apps: tracing prompts/responses, cost tracking

## Common mistakes

| Mistake | Why it happens | Fix |
| --- | --- | --- |
| Starting with orchestration first | Core model behavior may be obscured | Begin with the core ML/DL layer |
| Using multiple frameworks without need | Operational complexity grows | Add a framework for a concrete requirement |
| Ignoring deployment | A local demo may not match production | Continue into serving/MLOps |

## When not to use it

| Situation | Better choice |
| --- | --- |
| You already have a proven stack | Use the specific reference you need |
| You need model theory | Use the learning tracks |
