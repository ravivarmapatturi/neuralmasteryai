# Supervised Learning

The [overview](/docs/machine-learning/overview) defined learning as choosing a function that does well on new examples, and [ML Workflow Fundamentals](/docs/machine-learning/ml-workflow-fundamentals) showed how to measure that honestly. This page covers the most common setting, supervised learning, where every training example comes with the right answer. It shows that choosing a loss already decides what the ideal prediction is, before any model is chosen; it lays out the model families in this section by the assumption each one makes about the data; it measures what those assumptions do when a model is asked about inputs unlike its training data; and it covers combining models. Each family links to its own full-depth page.

<ELI5>

A child learning to estimate how far away things are gets told the right answer each time: "that tree is about 50 metres", "that car is about 200 metres". After enough examples, they can guess distances to things they've never been told about. That's supervised learning: examples with answers, then guesses for new cases.

How the child gets graded changes what they learn. If being off by a lot is punished much more than being off by a little, they learn to avoid big mistakes. If every metre of error counts the same, they learn something slightly different. And how they think about distance (using the size of familiar objects, or how hazy things look) decides which situations they'll get right. Everything below is those two ideas made exact.

</ELI5>

## 1. The Setup

Training data is a set of pairs $(\mathbf{x}_i, y_i)$: an input, usually a vector of $d$ **features**, and its **label** or **target**. The goal is a function $f$ that predicts $y$ from $\mathbf{x}$ well on new pairs from the same source. Two kinds of target split the field:

- **Regression**: $y$ is a number. A house price, a temperature, a time to delivery.
- **Classification**: $y$ is one of $K$ categories. Spam or not; which of 10 digits; which of 3 grape varieties. Most classifiers output a probability for each class, $\hat{P}(y = k \mid \mathbf{x})$, and the predicted class is the most probable one, or whichever a cost-based threshold picks (see [Model Evaluation](/docs/machine-learning/model-evaluation-metrics#threshold-optimization)).

Some problems have a richer target: a ranking, a time until an event that may not have happened yet, a whole sequence. Section 6 points to the pages for those.

In both main cases, training means minimizing an average **loss** over the training data, usually plus a penalty on complexity. The next section shows that the loss does more than score mistakes: it determines what the perfect model would predict.

## 2. The Loss Decides the Target

Suppose we had unlimited data and unlimited flexibility, so the model could predict anything at all for each input. What would minimizing each loss make it predict? At a single input $\mathbf{x}$, the label is still uncertain (two houses with identical features sell for different prices), so the question is: which single prediction $c$ minimizes the *expected* loss over that uncertainty? The answer is different for each loss.

**Squared error, $L = (y - c)^2$.** The expected loss is $\mathbb{E}[(y - c)^2 \mid \mathbf{x}]$. Differentiate with respect to $c$ and set it to zero:

$$
\frac{d}{dc}\,\mathbb{E}\big[(y - c)^2 \mid \mathbf{x}\big] = -2\,\mathbb{E}[y - c \mid \mathbf{x}] = 0 \quad\Rightarrow\quad c^* = \mathbb{E}[y \mid \mathbf{x}]
$$

The best prediction under squared error is the **conditional mean**. Every regression model trained with squared error, from [linear regression](/docs/machine-learning/linear-regression) to a neural network, is trying to estimate the average outcome for each input.

**Absolute error, $L = \lvert y - c\rvert$.** The derivative of $\lvert y - c\rvert$ with respect to $c$ is $-1$ when $y \gt  c$ and $+1$ when $y \lt  c$, so the derivative of the expected loss is $P(y \lt  c \mid \mathbf{x}) - P(y \gt  c \mid \mathbf{x})$. It's zero when half the probability is on each side:

$$
c^* = \operatorname{median}(y \mid \mathbf{x})
$$

**Quantile (pinball) loss**, which weights under- and over-predictions by $\tau$ and $1-\tau$, generalizes this to $c^* = $ the $\tau$-quantile, which is how prediction intervals are built ([Uncertainty Estimation](/docs/machine-learning/uncertainty-estimation-and-conformal-prediction)).

**Zero-one loss for classification** ($L = 1$ if wrong, 0 if right). The expected loss of predicting class $c$ is $1 - P(y = c \mid \mathbf{x})$, minimized by the most probable class: the **Bayes classifier** ([derived on the Naive Bayes page](/docs/machine-learning/naive-bayes-lda-qda)). Zero-one loss can't be minimized with gradients, so classifiers train with a smooth stand-in: cross-entropy (log loss), whose minimizer is the true probability $P(y = k \mid \mathbf{x})$ itself, or the hinge loss of [SVMs](/docs/machine-learning/support-vector-machines), whose minimizer is the sign of the most probable class.

The difference matters whenever the target is skewed. In Section 7, for a log-normal target shaped like incomes, the best constant under squared error is 1.65 and under absolute error 1.00: the mean and the median, 65% apart. A model trained with squared error to predict "typical" salaries will be pulled up by the few very high ones. Choose the loss to match the question being asked.

## 3. The Model Families and Their Bets

The loss fixes what we're estimating. The model decides how we estimate it from finite data, and every model does so by making an assumption about what kind of function the answer is, its **inductive bias** (see the [no-free-lunch discussion](/docs/machine-learning/overview)). The families in this section:

| Family | The bet it makes | Strengths | Weak spots | Page |
|---|---|---|---|---|
| Linear models | Effects add up, each feature with a fixed weight | Interpretable, fast, extrapolate linearly, need little data | Can't capture interactions or curves without engineered features | [Linear](/docs/machine-learning/linear-regression), [Ridge](/docs/machine-learning/ridge-regression), [Lasso](/docs/machine-learning/lasso-regression), [Elastic Net](/docs/machine-learning/elastic-net), [Logistic](/docs/machine-learning/logistic-regression) |
| Decision trees | The answer is constant within axis-aligned boxes | Readable, any feature scale, interactions for free | Unstable, staircase boundaries | [Decision Trees](/docs/machine-learning/decision-tree) |
| Tree ensembles | Many trees, averaged or added, are smoother and steadier than one | Best default for tabular accuracy | Less readable; can't extrapolate | [Random Forest](/docs/machine-learning/random-forest), [Boosting](/docs/machine-learning/boosting), [XGBoost, LightGBM & CatBoost](/docs/machine-learning/xgboost-lightgbm-catboost) |
| Margin and kernel methods | The widest gap between classes generalizes; similarity to key examples decides | Strong in high dimensions with modest $n$ | Slow beyond about $10^5$ examples; need scaling | [SVM & SVR](/docs/machine-learning/support-vector-machines) |
| Nearest neighbours | Similar inputs have similar outputs | No training; adapts to any boundary | Curse of dimensionality; needs scaling; slow queries | [k-NN](/docs/machine-learning/k-nearest-neighbors) |
| Generative classifiers | Each class follows a simple distribution | Very little data needed if the assumption holds | Wrong assumptions give wrong, overconfident probabilities | [Naive Bayes, LDA & QDA](/docs/machine-learning/naive-bayes-lda-qda) |

The [SGD page](/docs/machine-learning/sgd-classifier-regressor) shows that the linear rows are one model trained by one loop with different losses, and the [overview's table](/docs/machine-learning/overview) shows every algorithm as a choice of model, loss and optimizer.

**Parametric and non-parametric.** A second way to sort them is by whether the model's size is fixed. A **parametric** model has a fixed number of parameters whatever the amount of data: a linear model with $d$ features has $d + 1$. It can only ever represent functions of its fixed form, which limits both how wrong it can be on small data and how right it can get on large data. A **non-parametric** model grows with the data: k-NN stores every example, a fully grown tree adds leaves as data arrives, a kernel SVM keeps a growing set of support vectors. These can represent nearly any function given enough data (k-NN is [universally consistent](/docs/machine-learning/k-nearest-neighbors)), but they need more data to do it, and they say little about regions with no data at all.

## 4. What Happens Away From the Data

That last point is easy to overlook, and it's where the bets show most clearly. Inside the range of the training data, a flexible model can follow almost any pattern. Outside it, each model does whatever its bias dictates:

- A **linear model** extends its line forever.
- A **tree or tree ensemble** predicts the constant of the nearest edge leaf: a flat line beyond the last split.
- **k-NN** predicts the average of the nearest training points, which are all at the edge: also flat.
- A **kernel SVM with an RBF kernel** decays toward its intercept far from every support vector.

Section 7 trains four models on $y = 0.5x + \sin(2x) + \text{noise}$ for $x$ between 0 and 6, then tests them both inside that range and on $x$ from 8 to 10. Inside, the flexible models win easily: errors of 0.11 to 0.15 against 0.67 for the straight line, which can't follow the wiggle. Outside, the ranking flips: the straight line has the smallest error (1.08), because it at least continues the upward trend, while the tree, k-NN and gradient boosting all predict a flat continuation of the last values they saw and are off by 2.2 to 2.5.

Neither model is "right" out there; the data says nothing about $x = 9$. The lesson is to know what your model will do when it's asked, because in production it will be: next year's prices, a new customer segment, a sensor reading beyond the usual range. Tree models are the default for tabular data and they cannot extrapolate a trend. Common responses are to model the trend separately (fit a linear trend, then a tree model on the residuals), to add features that carry the trend, or to monitor for inputs outside the training range.

## 5. Combining Models

Different models make different mistakes, and combining them can cancel some of those mistakes out. Three ways, from simplest to most involved:

**Averaging** (voting, for classifiers). Train several models and average their predictions. By the variance formula derived on the [Random Forest page](/docs/machine-learning/random-forest), $\operatorname{Var}(\text{average}) = \rho\sigma^2 + \tfrac{1-\rho}{B}\sigma^2$, this helps most when the models are accurate and their errors are weakly correlated: models of different families tend to disagree in useful ways. **Bagging** applies it to many copies of one model trained on bootstrap samples.

**Boosting** trains models in sequence, each fitted to the errors of the ones before, reducing bias rather than variance ([Boosting](/docs/machine-learning/boosting)).

**Stacking** (Wolpert, 1992) learns how to combine. Train several base models, then train a **meta-model** whose inputs are the base models' predictions and whose target is the true label. The essential detail is that the meta-model must be trained on predictions the base models made for examples *they weren't trained on*, produced by cross-validation; otherwise it learns to trust whichever base model overfits the training set most. scikit-learn's `StackingClassifier` and `StackingRegressor` do this internally.

In Section 7, stacking a logistic regression on top of four classifiers (logistic regression, an SVM, k-NN and a random forest) on the breast-cancer data gives a cross-validated log loss of 0.0724, slightly better than the best single model (logistic regression, 0.0738), and much better than the worst (k-NN, 0.226). The gain is small, which is typical: stacking reliably matches the best base model and sometimes beats it by a little, at the cost of training and running all of them. It's a staple of competitions and used sparingly in production.

<GoDeeper title="Go deeper: multi-class from binary, and multi-label">

Some classifiers handle many classes natively: trees, k-NN, naive Bayes, LDA, and logistic regression through the softmax. Others are inherently binary, the SVM most of all. Two standard reductions turn a binary method into a $K$-class one:

- **One-vs-rest**: train $K$ classifiers, each separating one class from all the others, and predict the class whose classifier is most confident. $K$ models, each trained on all the data; the "rest" side is often much larger than the "one" side.
- **One-vs-one**: train a classifier for every pair of classes, $K(K-1)/2$ models, each on only the two classes' data, and predict by majority vote. More models, but each is smaller and balanced. scikit-learn's `SVC` uses this internally.

**Multi-label** problems are different again: each example can have several labels at once (a photo containing both a dog and a beach). The simplest approach trains one independent binary classifier per label; **classifier chains** feed each label's prediction into the next classifier, so correlations between labels (beaches and swimsuits) can be used. The evaluation metrics change too, to per-label averages such as micro- or macro-averaged F1 (see [Model Evaluation](/docs/machine-learning/model-evaluation-metrics#classification-metrics)).

</GoDeeper>

## 6. Problems With Their Own Structure

Some supervised problems don't fit the plain "one input, one label, independent examples" mould, and each has its own page because the evaluation, and often the loss, has to change:

- **[Time series forecasting](/docs/machine-learning/time-series-forecasting)**: the examples are ordered and dependent, so random splits leak the future; models use the past of the series itself.
- **[Survival analysis](/docs/machine-learning/survival-analysis)**: the target is a time until an event, and for some subjects the event hasn't happened yet (censoring), which plain regression mishandles.
- **[Recommender systems](/docs/machine-learning/recommender-systems)** and **[learning to rank](/docs/machine-learning/learning-to-rank)**: the target is a preference or an ordering, and the metric (such as NDCG) cares about the top of a list, not each prediction alone.

## 7. Minimal Implementation

Three experiments, one per idea above: the best constant under each loss for a skewed target (Section 2); four models inside and outside their training range (Section 4); and stacking on a real dataset (Section 5):

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import HistGradientBoostingRegressor, RandomForestClassifier, StackingClassifier
from sklearn.linear_model import LinearRegression, LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.neighbors import KNeighborsClassifier, KNeighborsRegressor
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
from sklearn.tree import DecisionTreeRegressor

# 1. The loss decides what the best constant prediction is
rng = np.random.default_rng(0)
y = rng.lognormal(mean=0.0, sigma=1.0, size=100_000)        # skewed, like incomes or house prices
grid = np.linspace(0, 4, 4001)
sq = [np.mean((y - c) ** 2) for c in grid[::10]]
ab = [np.mean(np.abs(y - c)) for c in grid[::10]]
print(f"best constant under squared error {grid[::10][np.argmin(sq)]:.2f}   mean   {y.mean():.2f}")
print(f"best constant under absolute error {grid[::10][np.argmin(ab)]:.2f}   median {np.median(y):.2f}")

# 2. Inductive bias: train on x in [0, 6], test inside and outside that range
x = rng.uniform(0, 6, 300); t = 0.5 * x + np.sin(2 * x) + rng.normal(0, 0.2, 300)
x_in = np.linspace(0, 6, 200); x_out = np.linspace(8, 10, 200)
truth = lambda z: 0.5 * z + np.sin(2 * z)
print("model                  error inside training range   error outside (x in 8..10)")
for name, m in [("linear regression", LinearRegression()),
                ("decision tree (depth 6)", DecisionTreeRegressor(max_depth=6)),
                ("k-NN (k=10)", KNeighborsRegressor(10)),
                ("gradient boosting", HistGradientBoostingRegressor())]:
    m.fit(x[:, None], t)
    rmse = lambda z: np.sqrt(np.mean((m.predict(z[:, None]) - truth(z)) ** 2))
    print(f"{name:24s} {rmse(x_in):>8.3f}                  {rmse(x_out):>8.3f}")

# 3. Stacking: a logistic regression learns how to combine four different models
X, yb = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(5, shuffle=True, random_state=0)
base = [("lr", make_pipeline(StandardScaler(), LogisticRegression())),
        ("svm", make_pipeline(StandardScaler(), SVC(probability=True, random_state=0))),
        ("knn", make_pipeline(StandardScaler(), KNeighborsClassifier(15))),
        ("rf", RandomForestClassifier(random_state=0))]
for name, m in base + [("stacked", StackingClassifier(base, final_estimator=LogisticRegression(), cv=5))]:
    s = cross_val_score(m, X, yb, cv=cv, scoring="neg_log_loss")
    print(f"{name:8s} cross-validated log loss {-s.mean():.4f}")
```

Output (scikit-learn 1.7):

```
best constant under squared error 1.65   mean   1.65
best constant under absolute error 1.00   median 1.00
model                  error inside training range   error outside (x in 8..10)
linear regression           0.666                     1.084
decision tree (depth 6)     0.140                     2.163
k-NN (k=10)                 0.107                     2.399
gradient boosting           0.149                     2.510
lr       cross-validated log loss 0.0738
svm      cross-validated log loss 0.0867
knn      cross-validated log loss 0.2260
rf       cross-validated log loss 0.1162
stacked  cross-validated log loss 0.0724
```

- **Losses pick targets.** A brute-force search for the best constant lands exactly on the mean under squared error (1.65) and the median under absolute error (1.00), as derived in Section 2.
- **Flexible inside, flat outside.** The three flexible models fit the curve about five times better than the line inside the training range, and do about twice as badly as the line from 8 to 10.
- **Stacking edges out the best model.** Log loss 0.0724 against 0.0738 for logistic regression alone. On this nearly linear dataset, the simplest base model was already close to the best possible.

## 8. When *Not* to Use Supervised Learning

| Situation | Better approach |
|---|---|
| You have no labels and can't get them | [Unsupervised learning](/docs/machine-learning/unsupervised-learning): clustering, dimensionality reduction, anomaly detection |
| Labels are expensive but unlabelled data is plentiful | Semi-supervised or self-supervised pretraining, then a small supervised model on the learned features |
| The labels are themselves unreliable or biased (past decisions, not outcomes) | Fix the labels first; a model trained on biased decisions learns to repeat them |
| You need the effect of an action, not a prediction | Causal inference or a randomized experiment; supervised models predict under the data's existing patterns |
| The model will act and its actions change future data (recommendations, pricing) | Bandits or reinforcement learning, which account for the feedback loop |
| Inputs at prediction time will lie far outside the training range | A model whose extrapolation you understand (Section 4), plus monitoring for out-of-range inputs |

## Remember

| Idea | In one line |
|---|---|
| Setup | Pairs $(\mathbf{x}, y)$; regression if $y$ is a number, classification if it's a category |
| Squared error | Optimal prediction is the conditional mean $\mathbb{E}[y \mid \mathbf{x}]$ |
| Absolute error | Optimal prediction is the conditional median |
| Zero-one loss | Optimal prediction is the most probable class (the Bayes classifier) |
| Cross-entropy | Its minimizer is the true class probability |
| Inductive bias | Every family assumes a kind of function; pick the bet that matches the data |
| Parametric vs non-parametric | Fixed size vs growing with data; the latter need more data, assume less |
| Extrapolation | Lines continue; trees, ensembles and k-NN go flat beyond the data |
| Combining | Average decorrelated models; boost to cut bias; stack with out-of-fold predictions |
| Special structure | Time series, survival, ranking: change the evaluation, not only the model |
