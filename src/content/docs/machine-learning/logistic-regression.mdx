# Logistic Regression, In Full Depth

[Linear Regression](/docs/machine-learning/linear-regression) predicts a number. Many questions want a yes or no instead: will this email be spam, will this patient be readmitted, will this student pass. Logistic regression answers them with the same linear core, $\mathbf{w}^T\mathbf{x} + b$, passed through one extra function that turns it into a probability. Despite the name, it's a classification method. This page derives it in full: the sigmoid and what the weights mean, the loss that comes out of the probability model and why squared error is the wrong one, the gradient and the curvature, how the solvers use them, what happens when the classes can be perfectly separated, the extension to many classes, and whether the probabilities can be trusted.

<ELI5>

Imagine sorting emails into "spam" and "not spam". A flat yes or no throws information away; you'd rather hear "92% sure this is spam", so obvious spam and borderline cases can be treated differently.

Logistic regression adds up evidence the way linear regression does: each word or feature adds or subtracts a few points. Then, instead of reporting the raw score, which could be anything from minus a thousand to plus a thousand, it squeezes the score into a number between 0 and 1 that behaves like a probability. Only at the very end does it draw a line: above 50%, call it spam. Everything below is that idea made exact.

</ELI5>

## 1. From a Score to a Probability

Linear regression's output is an unbounded number. For a yes-or-no target coded as $y \in \{0, 1\}$, fitting a straight line directly (the "linear probability model") gives predictions like $-0.3$ or $1.4$, which can't be probabilities, and a single extreme example can tilt the line enough to move every other prediction.

Logistic regression keeps the linear score

$$
z = \mathbf{w}^T\mathbf{x} + b
$$

and models the *probability* of class 1 as a smooth, S-shaped function of it:

$$
\hat{p} = P(y = 1 \mid \mathbf{x}) = \sigma(z)
$$

The score can be anything; the probability can't. The sections below derive the function $\sigma$, the loss used to fit $\mathbf{w}$ and $b$, and how they're solved. ## 2. The Sigmoid and the Log-Odds

### The Sigmoid Function

The function is the **logistic sigmoid**:

$$
\sigma(z) = \frac{1}{1 + e^{-z}}
$$

<ThemedImage alt="The sigmoid curve rising from 0 to 1, crossing 0.5 at z = 0, with predict class 0 to the left and predict class 1 to the right" sources={{light: sigmoidLight, dark: sigmoidDark}} />

Read it off the formula. As $z \to +\infty$, $e^{-z} \to 0$ and $\sigma(z) \to 1$. As $z \to -\infty$, $e^{-z}$ blows up and $\sigma(z) \to 0$. At $z = 0$, $\sigma(0) = \tfrac{1}{2}$. It's symmetric, $\sigma(-z) = 1 - \sigma(z)$, steepest at $z = 0$, and flattens out in both tails. To turn the probability into a class, threshold it: predict 1 when $\hat{p} \ge 0.5$, which is the same as predicting 1 when $z \ge 0$.

**Why this function and not some other S-curve?** Invert it. Solve $p = 1/(1 + e^{-z})$ for $z$:

$$
1 + e^{-z} = \frac{1}{p} \;\;\Rightarrow\;\; e^{-z} = \frac{1-p}{p} \;\;\Rightarrow\;\; z = \log\frac{p}{1-p}
$$

The quantity $p/(1-p)$ is the **odds** (a probability of 0.75 is odds of 3 to 1), and its logarithm is the **log-odds** or **logit**. So the model is

$$
\log\frac{P(y=1 \mid \mathbf{x})}{P(y=0 \mid \mathbf{x})} = \mathbf{w}^T\mathbf{x} + b
$$

Logistic regression is *linear regression on the log-odds*. The log-odds range over all real numbers, so a linear function is a natural model for them, and the sigmoid is simply the function that converts log-odds back into a probability.

**What a weight means.** Increase feature $j$ by one unit, holding the others fixed. The log-odds go up by exactly $w_j$, so the odds are multiplied by $e^{w_j}$, the **odds ratio**. In the example in Section 9, the fitted weight on hours studied is 1.19, so each extra hour multiplies the odds of passing by $e^{1.19} = 3.29$. That's the same multiplier everywhere, but its effect on the *probability* isn't: going from 4 to 6 hours moves the pass probability from 0.22 to 0.75, while going from 9 to 11 hours barely moves it, because the curve is already flat near 1. Weights are constant on the log-odds scale, not the probability scale.

## 3. The Loss Comes From the Probability Model

### The Cost Function: Binary Cross-Entropy

The model says each label is a coin flip with probability $\hat{p}^{(i)}$ of landing on 1. The standard way to fit a probability model is to choose the parameters that make the observed labels most likely, which gives the loss directly (the full derivation is in the box below):

$$
J(\mathbf{w}, b) = -\frac{1}{n}\sum_{i=1}^n \left[y^{(i)}\log\hat{p}^{(i)} + \left(1-y^{(i)}\right)\log\left(1-\hat{p}^{(i)}\right)\right]
$$

Only one term is active for each example, because $y^{(i)}$ is 0 or 1:

- If $y^{(i)} = 1$, the loss is $-\log\hat{p}^{(i)}$: near 0 when the model says $\hat{p} \approx 1$, and growing without limit as $\hat{p} \to 0$. Saying "0.1% chance" about something that happened costs $-\log 0.001 \approx 6.9$; saying 50% costs 0.69.
- If $y^{(i)} = 0$, the loss is $-\log(1 - \hat{p}^{(i)})$, the mirror image.

This is **binary cross-entropy**, the two-class case of the cross-entropy from [Probability & Statistics](/docs/mathematics-for-ai/probability-statistics#entropy-cross-entropy-and-kl-divergence). It's also called **log loss**.

<GoDeeper title="Go deeper: derive cross-entropy from the Bernoulli likelihood">

Same move as [linear regression's Gaussian-noise derivation](/docs/machine-learning/linear-regression#2-the-cost-function-mean-squared-error), with a different distribution. A single label $y \in \{0,1\}$ with $P(y = 1) = \hat{p}$ has the Bernoulli distribution, which can be written as one formula covering both cases:

$$
P\left(y \mid \mathbf{x}\right) = \hat{p}^{\,y}\,(1-\hat{p})^{1-y}
$$

Check it: when $y = 1$ the second factor is $(\cdot)^0 = 1$, leaving $\hat{p}$; when $y = 0$ the first factor disappears, leaving $1 - \hat{p}$.

For $n$ independent examples the likelihood is the product of these, and the logarithm turns the product into a sum:

$$
\log L(\mathbf{w}, b) = \sum_{i=1}^{n}\left[y^{(i)}\log\hat{p}^{(i)} + \left(1-y^{(i)}\right)\log\left(1-\hat{p}^{(i)}\right)\right]
$$

Maximizing $\log L$ is the same as minimizing $-\log L$, and dividing by $n$ doesn't move the minimum, so minimizing $-\tfrac{1}{n}\log L$ is exactly minimizing $J$. Cross-entropy isn't an invented penalty that happens to behave well; it is the negative log-likelihood of the model, the direct analogue of how Gaussian noise produces squared error (see [MLE vs MAP](/docs/mathematics-for-ai/probability-statistics#mle-vs-map)).

</GoDeeper>

### Why Not Just Use MSE Loss?

Plugging $\hat{p}$ into squared error, $\tfrac{1}{n}\sum(\hat{p}^{(i)} - y^{(i)})^2$, runs, but it trains badly, for two reasons you can see in the derivative.

By the chain rule, the gradient of $(\hat{p} - y)^2$ with respect to the score $z$ is

$$
\frac{\partial}{\partial z}(\hat{p} - y)^2 = 2(\hat{p} - y)\cdot\sigma'(z) = 2(\hat{p} - y)\,\hat{p}(1 - \hat{p})
$$

using $\sigma'(z) = \hat{p}(1-\hat{p})$ (derived in Section 4). The factor $\hat{p}(1-\hat{p})$ is at most 0.25 and goes to zero in both tails. So when the model is *confidently wrong*, say $\hat{p} = 0.001$ for an example with $y = 1$, the error term is nearly 1 but the gradient is multiplied by about 0.001. The examples that most need correcting barely move the weights. That's the flat-lining the studio's Gradient Descent Lab shows.

The second problem is the shape of the surface. Composing the sigmoid with squared error gives a **non-convex** function of $\mathbf{w}$: it has flat plateaus and, with many examples, can have many local minima (Auer, Herbster and Warmuth, 1996, constructed cases with exponentially many). Cross-entropy, as the next section proves, is convex, so there is one minimum and any descent method finds it.

## 4. The Gradient and the Curvature

### Deriving the Gradient

Working through the chain rule from the loss to the score to the weights, the sigmoid's derivative cancels against the log-loss derivative and leaves something very simple:

$$
\frac{\partial J}{\partial w_j} = \frac{1}{n}\sum_{i=1}^n \left(\hat{p}^{(i)} - y^{(i)}\right)x_j^{(i)} \qquad\qquad \frac{\partial J}{\partial b} = \frac{1}{n}\sum_{i=1}^n \left(\hat{p}^{(i)} - y^{(i)}\right)
$$

or, for all weights at once, $\nabla_{\mathbf{w}}J = \tfrac{1}{n}X^T(\hat{\mathbf{p}} - \mathbf{y})$.

<GoDeeper title="Go deeper: watch the cancellation happen, term by term">

Work with one example at a time: drop the $(i)$ and the $\tfrac1n$, and restore both at the end. Let $\ell = -\left[y\log\hat{p} + (1-y)\log(1-\hat{p})\right]$, with $\hat{p}=\sigma(z)$ and $z=\mathbf{w}^T\mathbf{x}+b$. The chain is $\ell \to \hat{p} \to z \to w_j$.

**Step 1, $\partial \ell/\partial \hat{p}$:** differentiate each log term ($\tfrac{d}{dp}\log p = \tfrac1p$ and $\tfrac{d}{dp}\log(1-p) = \tfrac{-1}{1-p}$):

$$
\frac{\partial \ell}{\partial \hat{p}} = -\frac{y}{\hat{p}} + \frac{1-y}{1-\hat{p}}
$$

**Step 2, $\partial \hat{p}/\partial z = \sigma'(z)$:** from $\sigma(z) = (1+e^{-z})^{-1}$,

$$
\sigma'(z) = \frac{e^{-z}}{(1+e^{-z})^2} = \underbrace{\frac{1}{1+e^{-z}}}_{\sigma(z)}\cdot\underbrace{\frac{e^{-z}}{1+e^{-z}}}_{1-\sigma(z)} = \hat{p}(1-\hat{p})
$$

**Step 3, multiply:**

$$
\frac{\partial \ell}{\partial z} = \left(-\frac{y}{\hat{p}}+\frac{1-y}{1-\hat{p}}\right)\hat{p}(1-\hat{p}) = -y(1-\hat{p}) + (1-y)\hat{p} = \hat{p}-y
$$

The $\hat{p}$ in the first denominator cancels against the $\hat{p}$ from $\sigma'(z)$, and $(1-\hat{p})$ cancels in the second term. What's left is the plain prediction error.

**Step 4:** $\partial z/\partial w_j = x_j$, so $\partial \ell/\partial w_j = (\hat{p}-y)x_j$. Restore the sum over examples and the $\tfrac1n$.

</GoDeeper>

**The same shape as linear regression.** Compare the [linear regression gradient](/docs/machine-learning/linear-regression#3-deriving-the-gradient-step-by-step): "prediction minus target, times input". The loss and the output function are both different, yet the gradient has the same form. That isn't a coincidence. Linear and logistic regression are both **generalized linear models**, each with its "canonical" link function (identity for Gaussian targets, logit for Bernoulli ones), and every GLM with its canonical link has this gradient. The same cancellation happens for softmax with cross-entropy (Section 7), which is why the output layer of every neural network classifier, and every language model's next-token loss, has a gradient of "predicted probabilities minus one-hot target".

**Convexity, proved.** Differentiate once more to get the Hessian, the matrix of second derivatives. Since $\partial(\hat{p} - y)/\partial z = \sigma'(z) = \hat{p}(1-\hat{p})$:

$$
H = \nabla^2_{\mathbf{w}}J = \frac{1}{n}\sum_{i=1}^n \hat{p}^{(i)}\left(1-\hat{p}^{(i)}\right)\mathbf{x}^{(i)}\mathbf{x}^{(i)T} = \frac{1}{n}X^TSX
$$

where $S$ is the diagonal matrix with entries $\hat{p}^{(i)}(1 - \hat{p}^{(i)})$, all positive. For any vector $\mathbf{v}$, $\mathbf{v}^TH\mathbf{v} = \tfrac1n\sum_i \hat{p}^{(i)}(1-\hat{p}^{(i)})(\mathbf{v}^T\mathbf{x}^{(i)})^2 \ge 0$, so the Hessian is positive semidefinite everywhere, and $J$ is convex. Any point where the gradient is zero is a global minimum. Notice that $y$ doesn't appear in $H$ at all; the curvature depends only on how confident the current predictions are.

## 5. Solving It

Unlike linear regression, setting $X^T(\hat{\mathbf{p}} - \mathbf{y}) = 0$ has no closed-form solution, because $\hat{\mathbf{p}}$ depends on $\mathbf{w}$ through the sigmoid. There are two families of solver.

**Gradient descent**, $\mathbf{w} \leftarrow \mathbf{w} - \eta\,\tfrac1n X^T(\hat{\mathbf{p}} - \mathbf{y})$, exactly as for linear regression. Simple, and the only option at very large scale, where it's run stochastically (see [SGD Classifier & Regressor](/docs/machine-learning/sgd-classifier-regressor)). It needs a learning rate and can take thousands of steps.

**Newton's method** uses the curvature as well: approximate $J$ by a quadratic around the current point and jump to that quadratic's minimum,

$$
\mathbf{w} \leftarrow \mathbf{w} - H^{-1}\nabla_{\mathbf{w}}J
$$

No learning rate, and near the optimum the number of correct digits roughly doubles each step (quadratic convergence). In Section 9 it reaches a gradient of $10^{-8}$ in seven steps where gradient descent used twenty thousand. Rearranged, each Newton step is a weighted least-squares problem with weights $S$, which is why statisticians call it **iteratively reweighted least squares (IRLS)**; it's how R's `glm` fits logistic regression. The cost is forming and solving with the $d \times d$ Hessian, $O(nd^2 + d^3)$ per step, which is fine for hundreds of features and too slow for millions.

**Quasi-Newton methods** sit in between: L-BFGS builds an approximation of the inverse Hessian from the last few gradients, getting most of Newton's speed at gradient-descent cost per step. It's scikit-learn's default solver for `LogisticRegression`. For L1-penalized models scikit-learn uses `liblinear` or `saga`, which handle the non-smooth penalty.

## 6. What the Model Can Separate

### The Decision Boundary

The predicted class flips where $\hat{p} = 0.5$, which is where $z = \mathbf{w}^T\mathbf{x} + b = 0$. That's a straight line in two dimensions, and a flat hyperplane in general. More than that, every probability level is a straight line: $\hat{p} = 0.9$ wherever $z = \log 9 \approx 2.2$, a line parallel to the boundary. The weight vector $\mathbf{w}$ points across them, from low probability to high, and its length sets how quickly the probability changes as you cross:

<ThemedImage alt="Two classes of points in 2-D with logistic regression's parallel straight-line contours of equal probability, the thick p = 0.5 line being the decision boundary" sources={{light: boundaryLight, dark: boundaryDark}} />

This is plain logistic regression's central limitation: it can only draw straight boundaries. If the classes are separated by a curve (one class inside a circle, say), the model can't represent it unless you add features that make the boundary linear in a new space, such as $x_1^2$, $x_2^2$ and $x_1x_2$. The model stays linear in its *parameters*, the same point the [linear regression page](/docs/machine-learning/linear-regression#1-the-hypothesis) makes about polynomial features. Otherwise you need a different model: a [kernel SVM](/docs/machine-learning/support-vector-machines), trees, or a neural network.

**The opposite problem: perfectly separable data.** If some straight line puts every class-1 example on one side and every class-0 example on the other, the unpenalized loss has *no minimum*. Take any separating $\mathbf{w}$ and multiply it by 2: every $z$ doubles in size, every $\hat{p}$ moves closer to the right answer, and the loss goes down. It keeps going down as $\lVert\mathbf{w}\rVert \to \infty$, approaching zero but never reaching it. Gradient descent keeps growing the weights forever; Newton's method fails because the Hessian becomes singular. Albert and Anderson (1984) characterized exactly when a finite maximum-likelihood estimate exists. Section 9 shows the weight on a separable toy dataset climbing from 2.2 to 3.6 to 5.0 as the number of steps grows tenfold each time. It's common in practice, with many features or rare classes, and the cure is the same as for overfitting.

### Regularized Logistic Regression

Add a penalty on the weights, exactly as in [Ridge](/docs/machine-learning/ridge-regression#the-ridge-cost-function) or [Lasso](/docs/machine-learning/lasso-regression#the-lasso-cost-function):

$$
J_{\text{reg}}(\mathbf{w}, b) = J(\mathbf{w}, b) + \frac{\lambda}{2}\lVert\mathbf{w}\rVert_2^2
$$

The penalty grows without limit as the weights do, so even on separable data there's now a finite minimum. It also adds $\lambda I$ to the Hessian, making the objective strictly convex with a unique solution. As with linear models, the L2 version shrinks all weights and the L1 version selects features.

This is the default in scikit-learn: `LogisticRegression()` uses an L2 penalty with `C=1.0`, where `C` is the *inverse* strength, $C = 1/(n\lambda)$ in this page's notation. Smaller `C` means stronger regularization. Because the penalty is on by default, the coefficients are shrunk even when you didn't ask for it; for unpenalized maximum likelihood (for instance, to report odds ratios), pass `penalty=None`, and expect a failure to converge if the data is separable.

## 7. More Than Two Classes

### Multi-Class: Softmax Regression

With $K$ classes, give each class its own weight vector and score, $z_k = \mathbf{w}_k^T\mathbf{x} + b_k$, and turn the $K$ scores into $K$ probabilities with the **softmax**:

$$
\hat{p}_k = \frac{e^{z_k}}{\sum_{m=1}^{K} e^{z_m}}
$$

Every $\hat{p}_k$ is positive and they sum to 1. With $K = 2$, $\hat{p}_1 = e^{z_1}/(e^{z_0} + e^{z_1}) = \sigma(z_1 - z_0)$, so binary logistic regression is softmax with one score fixed at 0. The loss is the negative log-probability of the true class, **categorical cross-entropy**, $\ell = -\log\hat{p}_y$, and the same cancellation as Section 4 gives

$$
\frac{\partial \ell}{\partial z_k} = \hat{p}_k - \mathbb{1}[k = y]
$$

"Predicted probability minus one-hot target", the multi-class version of $\hat{p} - y$. This exact layer and loss sit at the output of most neural network classifiers and every language model, where the "classes" are the tokens in the vocabulary (see [Training Pipeline](/docs/llms-genai/training-pipeline)). In practice softmax is computed after subtracting the largest score from all of them, which doesn't change the result but prevents $e^{z}$ from overflowing.

The alternative is **one-vs-rest**: fit $K$ separate binary models, each class against all others, and predict the class with the highest probability. It's simpler but the $K$ probabilities don't sum to 1. scikit-learn's `LogisticRegression` fits the softmax ("multinomial") version for multi-class targets with its default solver.

## 8. Are the Probabilities Any Good?

A classifier's probabilities are **calibrated** if, among all examples it scores at 0.8, about 80% are positive. Logistic regression tends to be well calibrated when its assumptions roughly hold, because maximum likelihood directly rewards getting the probabilities right: Niculescu-Mizil and Caruana (2005) found it among the best-calibrated classifiers out of the box, while methods like naive Bayes, SVMs and boosted trees needed recalibration. There are three common ways to lose that:

- **Strong regularization** pulls all probabilities toward the base rate, making the model under-confident.
- **Resampling the training data** (oversampling the rare class, SMOTE) changes the class balance the model believes in, so its probabilities are wrong for the real population (see [ML Workflow Fundamentals](/docs/machine-learning/ml-workflow-fundamentals#sampling-strategies)).
- **A misspecified model**: if the true log-odds aren't linear in the features, the probabilities will be systematically off in some regions.

Check calibration with a reliability diagram (see [Model Evaluation & Metrics](/docs/machine-learning/model-evaluation-metrics#classification-metrics)), and choose the decision threshold from the costs of each kind of mistake rather than defaulting to 0.5: with calibrated probabilities, if a false negative costs ten times a false positive, the cost-minimizing threshold is $1/11 \approx 0.09$.

## 9. Minimal Implementation

Gradient descent, Newton's method from Section 5, and scikit-learn's unpenalized fit, on 400 students whose pass probability follows a known logistic curve (true $w = 1.2$, $b = -6$, so 50% at 5 hours). Then a separable toy dataset, to watch Section 6's runaway weight:

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def fit_gradient_descent(X, y, lr=0.1, epochs=5000):
    n, d = X.shape
    w, b = np.zeros(d), 0.0
    for _ in range(epochs):
        error = sigmoid(X @ w + b) - y          # p_hat - y, Section 4
        w -= lr * X.T @ error / n
        b -= lr * error.mean()
    return w, b

def fit_newton(X, y, steps=7):
    Xb = np.column_stack([np.ones(len(X)), X])  # bias as a column of ones
    theta = np.zeros(Xb.shape[1])
    for k in range(steps):
        p = sigmoid(Xb @ theta)
        grad = Xb.T @ (p - y) / len(y)
        H = Xb.T @ (Xb * (p * (1 - p))[:, None]) / len(y)   # X^T S X / n, Section 5
        theta -= np.linalg.solve(H, grad)
        print(f"  newton step {k + 1}: |gradient| = {np.linalg.norm(grad):.1e}")
    return theta[1:], theta[0]

# Hours studied -> passed, generated from a known logistic model
rng = np.random.default_rng(0)
hours = rng.uniform(0, 10, 400)
p_true = sigmoid(1.2 * (hours - 5))             # true w = 1.2, b = -6
passed = (rng.random(400) < p_true).astype(float)
X = hours[:, None]

w_gd, b_gd = fit_gradient_descent(X, passed, lr=0.05, epochs=20000)
w_nt, b_nt = fit_newton(X, passed)
sk = LogisticRegression(penalty=None).fit(X, passed)
print(f"gradient descent: w={w_gd[0]:.3f} b={b_gd:.3f}")
print(f"newton (7 steps): w={w_nt[0]:.3f} b={b_nt:.3f}")
print(f"scikit-learn:     w={sk.coef_[0, 0]:.3f} b={sk.intercept_[0]:.3f}   (true w=1.2, b=-6)")
print(f"odds ratio per extra hour: {np.exp(w_nt[0]):.2f}")
print(f"P(pass | 4 h) = {sigmoid(w_nt[0] * 4 + b_nt):.3f},  P(pass | 6 h) = {sigmoid(w_nt[0] * 6 + b_nt):.3f}")

# Perfectly separable data: the unpenalized weight never settles
Xs = np.array([[1.0], [2.0], [3.0], [6.0], [7.0], [8.0]])
ys = np.array([0, 0, 0, 1, 1, 1], dtype=float)
for epochs in [1000, 10000, 100000]:
    w, b = fit_gradient_descent(Xs, ys, lr=0.5, epochs=epochs)
    print(f"separable, {epochs:>6} epochs: w={w[0]:.2f}")
print(f"separable, scikit-learn default (L2, C=1): w={LogisticRegression().fit(Xs, ys).coef_[0, 0]:.2f}")
```

## 10. When *Not* to Use Logistic Regression

| Situation | Better choice |
|---|---|
| The boundary between classes is strongly curved, and you can't engineer features that straighten it | Trees and boosting ([XGBoost, LightGBM, CatBoost](/docs/machine-learning/xgboost-lightgbm-catboost)), a [kernel SVM](/docs/machine-learning/support-vector-machines), or a neural network |
| Complex interactions between many features | Gradient-boosted trees, which find interactions automatically |
| Raw images, audio or text | Neural networks that learn the features; logistic regression is often their final layer |
| Perfectly or nearly separable data and you need unpenalized estimates | Firth's penalized likelihood, or report the separation; plain maximum likelihood doesn't exist |
| An ordered outcome (low, medium, high) | Ordinal logistic regression, which uses the ordering |
| Very many features and few examples, without regularization | Always regularize; L1 if you also want feature selection |

As a **baseline**, though, it's hard to beat: fast, convex, well calibrated, and interpretable through odds ratios. Fit it first; a more complex model has to earn its place by beating it on held-out data.

## Remember

| Idea | In one line |
|---|---|
| Model | $P(y = 1 \mid \mathbf{x}) = \sigma(\mathbf{w}^T\mathbf{x} + b)$, a linear model for the log-odds |
| Sigmoid | $1/(1 + e^{-z})$; its inverse is the logit $\log\frac{p}{1-p}$ |
| Weights | $+1$ unit of $x_j$ multiplies the odds by $e^{w_j}$, the odds ratio |
| Loss | Binary cross-entropy, the negative log-likelihood of a Bernoulli model |
| Not squared error | Its gradient has a $\hat{p}(1-\hat{p})$ factor that vanishes when confidently wrong; non-convex |
| Gradient | $\tfrac1n X^T(\hat{\mathbf{p}} - \mathbf{y})$, the same shape as linear regression |
| Hessian | $\tfrac1n X^TSX$ with $S = \operatorname{diag}(\hat{p}(1-\hat{p}))$: convex |
| Solvers | Gradient descent at scale; Newton/IRLS for small $d$; L-BFGS by default |
| Boundary | Straight: $\mathbf{w}^T\mathbf{x} + b = 0$; every probability level is a parallel line |
| Separable data | Weights diverge without a penalty; regularize |
| scikit-learn | L2 penalty on by default; `C` is the inverse strength |
| Many classes | Softmax, with gradient $\hat{p}_k - \mathbb{1}[k = y]$ |
| Probabilities | Usually well calibrated; resampling and strong regularization break that |
