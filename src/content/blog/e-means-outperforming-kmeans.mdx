# e-Means: Scaling k-Means to Billion-Vector Datasets in One-Tenth the Epochs

On 11 November 2026, researchers from Meta FAIR and École des Ponts ParisTech published [e-means: outperforming k-means (in one-tenth the epochs)](https://arxiv.org/abs/2611.09501) by Swann Bessa, Pierre-Emmanuel Mazaré, Gergely Szilvasy, Hugo Touvron, David Picard, Matthijs Douze, and Hervé Jégou (code released in `faiss/contrib/e_means`, interactive explorer at [e-means.github.io](https://e-means.github.io/)). The authors demonstrate that updating cluster statistics through an exponential moving average across streaming mini-batches matches or surpasses the loss of a 25-epoch Lloyd baseline in about 1.2 to 3 epochs (between 1.6 and 2.4 epochs across the VIBE benchmark; 1.4 to 2.6 epochs in the arXiv 2611.09501 Abstract). On an NVIDIA H100 GPU, this yields 10× to 45× wall-clock speedups over Flash-KMeans, and 8× to 15× speedups over Faiss CPU implementations, as reported by the authors.

Clustering modern datasets often means partitioning 10 billion high-dimensional embeddings into millions of centroids. When you run standard Lloyd's k-means on a collection that large, each pass touches every single vector in memory before adjusting a single centroid coordinate. By the end of this post, you will understand the exact mathematical update that powers e-means, how fitted scaling laws set batch sizes and decay rates without manual grid searches, how Lloyd emerges as an exact special case, and how to run a minimal implementation in pure NumPy.

## 1. Why k-means is everywhere, and why Lloyd fails at scale

Every retrieval-augmented generation (RAG) system, image search engine, and multimodal embedding pipeline relies on vector quantization. Inverted File (IVF) indexes in Faiss partition high-dimensional vector spaces into $k$ Voronoi cells so that queries search only the vectors assigned to the closest centroids rather than scanning the entire collection. When training these index codebooks, practitioners turn to **k-means clustering**, an unsupervised method that assigns points to their nearest centroid and repositions each centroid to the mean of its assigned points.

Stuart Lloyd formulated the standard alternating algorithm in 1957. Lloyd's algorithm executes two alternating operations per iteration:

1. **Assignment step**: Compute the squared Euclidean distance between every point $x_i$ and all $k$ centroids, assigning each point to its closest centroid.
2. **Update step**: Recompute every centroid as the exact arithmetic average of all points assigned to it across the entire dataset.

This full-batch structure creates an engineering bottleneck at scale. To partition $n = 10^9$ vectors into $k = 10^5$ centroids, a single Lloyd iteration must compute $10^{14}$ distance evaluations before taking a single optimization step. If the initial centroids are poorly positioned, an entire full-dataset pass is spent discovering that fact. In contrast, modern deep learning optimizers make continuous progress after every small mini-batch. Previous attempts to train k-means with mini-batches (such as Sculley's 2010 heuristic) updated centroids with decaying learning rates, but they suffered from high distortion, sensitivity to step sizes, and empty cluster collapse.

## 2. Tracking sufficient statistics with exponential moving averages

The central insight of e-means is to treat clustering as tracking two running sufficient statistics per cluster: a cumulative vector sum $S_j$ and an accumulated point count $N_j$. Instead of overwriting these statistics from scratch on each full dataset pass, e-means updates them across streaming mini-batches with an **exponential moving average** (EMA), an update rule that blends previous historical statistics with fresh batch observations using a smoothing factor $\alpha$.

When a mini-batch $B$ of vectors arrives:

1. Each vector $x \in B$ is assigned to its nearest existing centroid $c_j = S_j / N_j$.
2. We compute the batch-local sum $s_j = \sum_{x \in B, z_x = j} x$ and batch-local count $n_j = |\{x \in B : z_x = j\}|$ for each cluster $j$.
3. The running statistics update via the exponential moving average:
   $$S_j \leftarrow (1 - \alpha) S_j + \alpha \cdot s_j$$
   $$N_j \leftarrow (1 - \alpha) N_j + \alpha \cdot n_j$$
4. The centroid position updates directly:
   $$c_j = \frac{S_j}{N_j}$$

Notice what happens when the batch size $B$ equals the full dataset size $n$, and we set the smoothing parameter $\alpha = 1.0$. The historical terms $(1 - \alpha) S_j$ and $(1 - \alpha) N_j$ vanish to zero, leaving $S_j = s_j$ and $N_j = n_j$. The updated centroid is $c_j = s_j / n_j$, which is identical to Lloyd's algorithm. **Lloyd's classical algorithm is the special case of e-means where $B = n$ and $\alpha = 1$.**

## 3. The maths and a worked step by hand

To see how the numbers behave during a single mini-batch step, consider a toy 2D clustering problem with $k = 2$ clusters.

Suppose the two centroids currently sit at:
$$c_1 = [0.0, 0.0], \quad c_2 = [10.0, 10.0]$$

Each cluster stores its current running sum and running count:
$$S_1 = [0.0, 0.0], \quad N_1 = 10.0$$
$$S_2 = [100.0, 100.0], \quad N_2 = 10.0$$

We receive a mini-batch of 4 points:
$$x_1 = [1.0, 1.0], \quad x_2 = [2.0, 0.0], \quad x_3 = [9.0, 11.0], \quad x_4 = [10.0, 8.0]$$

We evaluate Euclidean distances to assign each point to its nearest centroid:
- $x_1$ and $x_2$ are closest to $c_1$ ($d^2 = 2$ and $4$, versus $162$ and $164$ to $c_2$).
- $x_3$ and $x_4$ are closest to $c_2$ ($d^2 = 2$ and $4$, versus $202$ and $164$ to $c_1$).

We sum the vectors and count assignments inside this batch:
$$s_1 = [1.0, 1.0] + [2.0, 0.0] = [3.0, 1.0], \quad n_1 = 2$$
$$s_2 = [9.0, 11.0] + [10.0, 8.0] = [19.0, 19.0], \quad n_2 = 2$$

Let the current smoothing rate be $\alpha = 0.20$. We compute the exponential moving average update:

For cluster 1:
$$S_1 \leftarrow (1 - 0.20)[0.0, 0.0] + 0.20[3.0, 1.0] = [0.60, 0.20]$$
$$N_1 \leftarrow (1 - 0.20)(10.0) + 0.20(2) = 8.0 + 0.40 = 8.40$$
$$c_1 = \frac{[0.60, 0.20]}{8.40} \approx [0.0714, 0.0238]$$

For cluster 2:
$$S_2 \leftarrow (1 - 0.20)[100.0, 100.0] + 0.20[19.0, 19.0] = [80.0, 80.0] + [3.80, 3.80] = [83.80, 83.80]$$
$$N_2 \leftarrow (1 - 0.20)(10.0) + 0.20(2) = 8.0 + 0.40 = 8.40$$
$$c_2 = \frac{[83.80, 83.80]}{8.40} \approx [9.9762, 9.9762]$$

Centroid $c_1$ moved smoothly toward the batch center of mass $[1.5, 0.5]$ without overreacting or discarding its prior positioning.

## 5. Scaling laws, cosine decay, and reviving dead clusters

Prior mini-batch k-means variants required manual trial-and-error hyperparameter tuning for batch sizes and step decays. The authors of e-means resolved this by establishing empirical scaling laws that formulate batch size $B$ and initial decay rate $\alpha_0$ directly from dataset size $n$, cluster count $k$, and dimension $d$:

1. **Scaling-law batch sizing**: The recommended batch size scales proportionally with the number of clusters, ensuring each cluster receives updates with sufficient frequency while fitting neatly in GPU SRAM.
2. **Cosine decay schedule**: The smoothing parameter $\alpha$ follows a cosine schedule across training steps $t \in [0, T-1]$, decaying from initial $\alpha_0$ down to $10\%$ of its initial value:
   $$\alpha(t) = 0.1\alpha_0 + 0.5(1 - 0.1)\alpha_0 \left(1 + \cos\left(\frac{\pi t}{T}\right)\right)$$
   High $\alpha$ in early iterations allows centroids to migrate rapidly across the feature space; lower $\alpha$ near the end stabilizes fine-grained cluster boundaries.
3. **Dead-cluster revival**: In any clustering procedure, an outlier centroid can end up with zero assigned points. e-means monitors $N_j$. When a cluster's effective count drops below a threshold, the algorithm splits the cluster with the highest within-cluster variance along its primary axis, assigning one half to revive the dead centroid.
4. **Exact finalization**: After completing the planned training epochs, e-means performs one final evaluation pass where each centroid is reset to the exact arithmetic mean of its assigned points, eliminating any lingering EMA lag.

## 6. Runnable code: Lloyd vs. e-means in NumPy

Here is a self-contained Python implementation showing one step of Lloyd alongside one step of e-means on synthetic 2D data. You can execute this directly:

<RunnableCode code={`import numpy as np

# Seeded toy 2D dataset with two Gaussian blobs
np.random.seed(42)
c1 = np.random.randn(20, 2) + np.array([2.0, 2.0])
c2 = np.random.randn(20, 2) + np.array([8.0, 8.0])
X = np.vstack([c1, c2])

def lloyd_step(data, centroids):
    dists = np.linalg.norm(data[:, None, :] - centroids[None, :, :], axis=2)
    labels = np.argmin(dists, axis=1)
    new_c = np.array([data[labels == j].mean(axis=0) for j in range(len(centroids))])
    loss = np.mean(np.min(dists**2, axis=1))
    return new_c, loss

def emeans_step(batch, centroids, S, N, alpha):
    dists = np.linalg.norm(batch[:, None, :] - centroids[None, :, :], axis=2)
    labels = np.argmin(dists, axis=1)
    k = len(centroids)
    new_S = np.zeros_like(S)
    new_N = np.zeros_like(N)
    for j in range(k):
        mask = (labels == j)
        s_j = batch[mask].sum(axis=0) if np.any(mask) else np.zeros(2)
        n_j = np.sum(mask)
        new_S[j] = (1 - alpha) * S[j] + alpha * s_j
        new_N[j] = (1 - alpha) * N[j] + alpha * n_j
    new_c = np.array([new_S[j] / new_N[j] if new_N[j] > 1e-7 else centroids[j] for j in range(k)])
    return new_c, new_S, new_N

init_c = np.array([[1.0, 5.0], [9.0, 4.0]])
c_lloyd, loss_lloyd = lloyd_step(X, init_c)

# Initialize e-means running statistics
S = init_c.copy() * 10.0
N = np.array([10.0, 10.0])
batch = X[:8]  # First mini-batch of 8 samples
c_emeans, S, N = emeans_step(batch, init_c, S, N, alpha=0.3)

all_dists = np.linalg.norm(X[:, None, :] - c_emeans[None, :, :], axis=2)
loss_emeans = np.mean(np.min(all_dists**2, axis=1))

print(f"Lloyd pass 1 full loss:  {loss_lloyd:.4f}")
print(f"e-means step 1 full loss: {loss_emeans:.4f}")

## 7. About 1.2–3 epochs instead of 25: 10–45× faster on GPU, 8–15× on CPU

The authors evaluated e-means across 24 embedding and synthetic configurations, including the VIBE embedding benchmark (Jääsaari et al., 2025: 11 datasets spanning text, code, image and multimodal embeddings, $d = 200$ to $3,072$, $k = 8,192$ or $16,384$) and Meta's DINO10B dataset (Siméoni et al., 2025). The quantitative gains reported by the authors ([e-means.github.io](https://e-means.github.io/) and [arXiv:2611.09501](https://arxiv.org/abs/2611.09501)) are:

- **Epoch efficiency**: Across a wide range of scales and datasets, e-means reaches a test loss below Lloyd's at 25 epochs in **1.2 to 3 epochs** (reported on [e-means.github.io](https://e-means.github.io/); specifically between 1.6 and 2.4 epochs across all 11 datasets of the VIBE benchmark, and 1.4 to 2.6 epochs reported in the arXiv:2611.09501 Abstract).
- **GPU wall-clock acceleration**: On H100 GPUs, at $n = 10\text{M}$ vectors with $k = 65,536$ clusters and at $n = 100\text{M}$ with $k = 262,144$, e-means reports a **10× to 45× wall-clock speedup** over Flash-KMeans (Section 4 of [arXiv:2611.09501](https://arxiv.org/abs/2611.09501); [e-means.github.io](https://e-means.github.io/)).
- **CPU acceleration**: Measured against Faiss on CPU, e-means reports an **8× to 15× wall-clock speedup** ([e-means.github.io](https://e-means.github.io/) and arXiv:2611.09501 Section 1).
- **Extreme-scale demonstration on DINO10B**: In the paper (arXiv:2611.09501 Abstract, Table 3, and Appendix M), the authors cluster **DINO10B** ($10^{10}$ 1,024-dimensional DINO embeddings into $k = 2^{24} \approx 16.7\text{M}$ clusters) on NVIDIA H100 GPUs. In Table 3 (page 6), e-means reaches Lloyd's 25-epoch test loss in only 2.5 epochs, requiring 779 GPU hours for exact assignment and 22.8 GPU hours with Inverted File (IVF) assignment.

Every figure above is cited directly from the authors' page and arXiv:2611.09501 as reported by the authors.

## 8. Where it breaks and what it does not replace

e-means is an optimization procedure for the k-means objective; it does not alter the geometric assumptions of k-means itself:

1. **Convex spherical geometries only**: Like all k-means algorithms, e-means minimizes squared Euclidean distance. It cannot separate concentric rings, intertwined spirals, or non-convex manifold structures. For manifold-shaped clusters, [Spectral Clustering](/docs/machine-learning/gmm-spectral-clustering) or [DBSCAN](/docs/machine-learning/dbscan-hdbscan) remain necessary.
2. **Preset cluster count**: e-means requires specifying the number of clusters $k$ in advance. It does not determine the optimal number of centroids automatically.
3. **Static datasets versus moving targets**: The authors note on [e-means.github.io](https://e-means.github.io/) that e-means is formulated for fixed, static datasets (as in vector search index construction and large-scale data curation), unlike codebook learning in VQ-VAEs where the underlying feature distribution continuously shifts during neural network training.

## Summary

e-means modernizes classical k-means by adopting standard practices from deep learning: mini-batch streaming, exponential moving average updates on sufficient statistics, cosine schedules, and variance-driven cluster splitting. It treats Stuart Lloyd's 1957 algorithm as a special case ($\alpha = 1, B = n$), eliminating the need for dozens of slow full-batch passes across large-scale vector indexes.
